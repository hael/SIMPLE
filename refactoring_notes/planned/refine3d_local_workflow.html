    refine3D_local workflow and architecture cleanup¶

    Contract and status¶

    Contract: FINAL for the existing local-continuation workflow and the behavior-preserving corrections requested from Hans's review of 0c4801f. The maintainer requested the remaining findings on 2026-10-28. Follow-up source changes are uncommitted on the current checkout. The maintainer reviews and accepts the diff; Hans's review recommendations do not imply acceptance of this implementation.

    Execution: the architecture cleanup passed the reviewed Linux fast gate, focused NU handoff and full integration gate on 2026-10-29. The subsequent iteration-reference correction passed the focused Linux staging suite, fast gate and full integration test recorded below. These passes do not establish recovery on the Streptavidin benchmark.

    Required outcome¶

    Use the existing refine3D refine=cont matcher for single-state continuation from saved poses and genuine half-maps. Remove avoidable startup particle passes by staging compatible references, committed sigmas and accumulator chains. Keep the existing iteration strategy and shared final reconstruction. The public behavior and restrictions are defined once in the local-refinement policy.

    The architecture cleanup must meet these requirements:

    1. The commander owns defaults, CLI validation, the single parameter constructor, workflow sampling/grid/low-pass policy, child-program calls and final reconstruction. State-specific work-project selection stays here because it executes the selection child.
    2. The startup controller owns the independent source preflight before parameter initialization, ordinary project loading/publication and reference/sigma/chain staging. Load the selected work project once for the staging operations.
    3. The startup strategy owns file destinations, copying, state remapping and cleanup. Provenance owns record publication, identity validation and marker names. A source path is not overwritten with its staged destination.
    4. Provenance has named private identity fields and a reusable validated record. Preflight validates reference constituents once; project matching and startup staging consume that snapshot. Preserve record version 2 and its serialized field order; this is not a new persistent format or a generic cache.
    5. Chain compatibility and project discovery each have one owner. Preserve each caller's different rejection, logging and cleanup behavior.
    6. Portable tests live beside their owners, have isolated fixtures and execute without the Linux rejection dispatcher. Keep all meaningful assertions.
    7. UI constructors add their command-specific controls explicitly. Their helper contains only common inputs. Preserve controls, choices and defaults; correct registration help to describe refine=greedy.

    No new program, CLI parameter, numerical threshold, CMake target, per-source compiler flag or change to NU filtering is part of this cleanup. Preserve the existing optimizer, final reconstruction and scientific acceptance criteria. No main-repository commit or push is authorized.

    Preserved behavior and decisions¶

    • Local selects continuous pose refinement. Auto retains discrete refinement and optional pose_cont=yes polishing. Base refine3D refine=cont stays available.
    • Local defaults to autoscale=no; auto defaults to yes. A deliberate crop and explicit trs are honored. Native sampling comes from project metadata.
    • The sample target remains 25,000. Automatic budgeting targets four updates per active particle, with the existing cap and a three-iteration minimum. Explicit maxits also sets minits and can override that minimum. Rotation and shift bounds apply around each iteration's seed pose.
    • state=X creates a single-state work project; frozen m_estimator=flex uses the positive applied-weight rows. Selection can invalidate sigma/chain reuse.
    • Source preflight requires the merged map and genuine even/odd files, compatible dimensions/sampling/extent, valid stored poses, binary half labels and selected particles in both half-sets. It runs before parameters can synthesize halves.
    • A valid producer record binds its constituents to the source project/state, ordered rows, halves, population and settings. Independent explicit external references retain their caller-supplied alignment/half contract. Same-lineage row or half changes cannot use that exception. These checks do not establish independent reconstruction or prove a common coordinate frame.
    • An absent record permits a logged legacy base pair. Incomplete, mixed or modified recorded sets fail preflight. Unverified derived products use the existing logged base-half fallback; missing FSC is rebuilt from half-maps.
    • Compatible NU reuse carries recorded filtered maps, local resolution, masks and matching LP. Unrecorded destination masks are removed. Source files and same-file copies are protected. Missing derivatives do not trigger a startup particle reconstruction.
    • Sigma reuse requires the canonical store and producer identity to match native geometry, ordered observations, halves, population and noise settings. Sigma estimates may lag poses. Validate both the source and the staged copy. A rejected or absent store uses the existing image-power bootstrap owner; no unconditional startup power/reconstruction pass is added.
    • A chain must match its backend, rows, halves, population, weights, saved poses, constituent identities and allowed grid/extent. Do not manufacture sufficient statistics from completed half-maps. Copy compatible artifacts with the manifest last; otherwise iteration 1 is a counted full update that seeds the chain.
    • refine3D_startup represents ordinary startup, chain reuse or chain seeding. It shares the temporary first-update transition across execution modes and restores the requested fraction/flags after seeding. trail_seed remains an internal transport/reconstruction handshake.
    • Preserve inline reconstruction from the matcher's particle buffer, volume-owned assembly/filtering and post-assembly sigma commit. Rebuild Cartesian matching references each iteration. Local does not become fixed-reference fitting.
    • Call calc_final_rec once. Its native-grid sigma checks and cropped fallback retain their own policy and cold-solve budget. A fixed-pose refine=sigma fallback is not a pose search, but can prepare a polar model. Do not relabel an iteration/partial map as a final all-particle reconstruction.

    Acceptance contract¶

    Existing assertions protect missing/invalid input rejection before directory creation, source preservation, same-file safety, constituent mutation, ordered rows, half/population/observation identity, lagged sigma/reference poses, exact chain poses, mask remapping/removal, matching LP and fractional transitions. The analytic impulse fixture has independently known FSC +1/-1 in every shell. No tolerance or acceptance floor changes are authorized.

    H19 also defines broader acceptance: no startup particle pass for a complete compatible bundle/store; volume-only recovery of missing derivatives; exactly one necessary sigma bootstrap; simulation-truth pose checks; fractional-update parity; and native/cropped, weighted-state and backend finalization. The current test table records coverage, not a claim that this whole matrix has passed.

    Any performance comparison must use the same project and settings as the old continuous-only route. Evaluate the native-grid default separately. Account for startup particle passes, end-to-end time, peak memory and preparation/matching/ assembly/sigma costs. Removing calls alone does not establish a speedup.

    The shared manifest predicate must accept equal identity and same-extent grid padding, and reject changed population, state layout, weights, component sizes, a larger prior grid or different extent. Its existing 1% extent tolerance is preserved. Assembly still discards invalid chains; local startup still refuses reuse. PCG's additional raw-header validation stays with its existing owner.

    Project discovery retains the previous-numbered-directory preference, including an empty latest directory, and leaves unique-project enforcement/diagnostics to the caller. Discovery does not create run directories or mutate the command line.

    Source-level UI comparison must preserve all 32 auto and 31 local input specifications, apart from corrected registration prose. Generated display defaults must remain identical. Linux compilation, affected unit suites, the fast gate and the focused positive NU-handoff test are required. Static checks alone establish neither runtime preservation nor reconstruction quality.
