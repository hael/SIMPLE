    The 2D structure aligned with 3D, and one project owner on the master¶

    Refactoring note, 2026-10-20. Completed 2026-10-20 (all items kept; the record is the "Progress" section, the summary the report structure2D_and_project_owner_report.md beside this note). The execution plan of the unattended run structure2D_owner on the Oracle Linux test machine (the Dell). The design comes from doc/implementation_notes/planned/speed_architecture_proposals.md (section 1.3, the row "one project owner on the master"; section 1.4 "The commanders used as library routines"; section 1.5 "Moved before the release", the 2D code structure) and from doc/implementation_notes/completed/identical_speed_run_review.md ("The master's project handling"). The code facts below were read at 34f314fe5 on 2026-10-20; line numbers are approximate, find the code by name.

    Rulings¶

    • 2026-10-19: the run takes the 2D structure first, then "one project owner on the master" for 3D and 2D, with no time limit. It starts by checking the last three speed changes on this machine's x86 build.
    • 2026-10-20, random generator: each moved body builds its own params today, and params%new reseeds the random generator (with SIMPLE_SEED set, seed = base + 7919 x the number of earlier seed_rnd calls, src/utils/math/simple_rnd.f90) and sets the thread count. No compatibility reseeds are kept: once a body runs on the master's own params, the later random draws change. How those steps are judged is in "The tests".
    • 2026-10-20, cfar and lp_est: when volume assembly works on the master's own project, the master sees cfar and lp_est of the current iteration instead of the previous one. Done as an isolated item after the rest, checked so that only cfar, lp_est and what reads them differ. The two items that need it (one write per iteration, and removing the last entry point) follow it.
    • 2026-10-18 (the accepted proposals): the bodies of volume assembly and the other master steps move out of the commanders. The simple-refine3d skill's statement that volume assembly is intentionally executed in the commander is superseded; the report proposes the new skill text.
    • Not in this run: the states' parallel assembly and the NU filter as an object (left alone, ruling of 2026-10-19), the worker fold, persistent workers, edits of stream code (src/main/stream, commanders/stream: Joe's area) and of the GUI (nice/).

    What the code is today¶

    3D. exec_refine3D (simple_commanders_refine3D.f90) runs the iteration loop and picks a strategy (create_refine3D_strategy, simple_refine3D_strategy.f90): distributed when nparts is set and part is not, shared memory otherwise. The matcher refine3D_exec (simple_strategy3D_matcher.f90) samples, searches, writes the orientations and sigma2 rows and writes the partial reconstructions of its particles. The strategy assembles the volumes and decides convergence (check_conv3D) in both modes.

    2D. exec_refine2D (simple_commanders_refine2D.f90) runs the loop and picks create_refine2D_strategy (simple_refine2D_strategy.f90) by the same rule. The matcher refine2D_exec (simple_strategy2D_matcher.f90) samples, searches and accumulates the class sums; then its finalize_restoration_and_convergence either writes the part's contribution (a distributed worker) or, in shared memory, restores the class averages (cavger_commit_carryover, cavger_restore_cavgs, cavger_gen2Dclassdoc, write_merged/write_eo), writes the cls2D/cls3D segments, runs check_conv2D, applies minits, maxits and full-assignment coverage, prints the verdict and writes the progress file. The distributed master assembles through the cavgassemble commander (simple_commanders_mkcavgs.f90, called from run_distributed_cavg_assembly) and decides convergence in the strategy. refine2D_exec is called by the shared-memory strategy and the worker commander only. The stream's 2D pool always runs distributed (prg=refine2D_distr, its workers prg=refine2D), never the shared-memory branch.

    The master's project in distributed refine3D. The strategy calls typed entry points added to commanders: commander_prob_align%execute_from_project (and the neighbourhood variant), commander_volassemble%execute_hand_on and commander_commit_sigma2%execute_from_project. Their bodies (run_prob_align and run_prob_align_neigh in simple_commanders_prob.f90, about 90 lines each; run_volassemble in simple_commanders_rec_distr.f90, about 530 lines, beside restore_state_from_parts and filter_pcg_nonuniform_maps; run_commit_sigma2 in simple_commanders_euclid.f90, about 100 lines) each build their own params and toolboxes from a command line and a copy of the master's project. A kept reprojection builder (refbuild, materialize_reprojection_model_kept) rereads the project and remakes volumes by hand every iteration. Per iteration (gridding, prob, Euclidean objective): two full project reads, four copies in memory, four writes of the particle segment plus the out segment. The 2D master does the same through execute(cline) of prob_align2D, cavgassemble (which writes the whole project) and the sigma commit: three full reads, two segment rereads, one full write and four segment writes per iteration.

    Other callers. Volume assembly is also reached through simple_rec3D_service%assemble_gridding (reconstruct3D, FLEX, the final reconstruction, the solve3D add-on); the sigma commit through the solve3D deferred commit and both 2D strategies; all of them through the private exec programs. These keep working through the commanders' execute(cline).

    Side effects of params%new in each body (simple_parameters_phases.f90): the reseed above, and omp_set_num_threads(nthr) with nthr_glob. A body that runs on the master's params must set the thread count it needs itself and the master must restore its own count after the call.

    The target¶

    • 2D like 3D. The 2D matcher searches, accumulates the class sums and writes orientations and sigma2 rows; a distributed worker also writes its contribution. Restoration of the class averages in shared memory and the convergence decision in both modes are strategy routines. refine2D is a public program, as refine3D is.
    • One project owner. The bodies of prob_align, prob_align_neigh, volume assembly, the sigma commit, prob_align2D and class-average assembly become strategy (or domain) routines that take the master's (params, build) and explicit arguments for what differs today through the command line (threads, which_iter, update_frac, combine_eo, state), as execute_rec3D_pcg_distributed_master(params, build, ...) already does. Each commander's execute(cline) builds its params and builder and calls the same routine. The distributed master materialises its reprojection model on its own builder (the kept builder goes), reads only what the workers write, and writes the project once per iteration, at the end of the iteration, so the file always holds a complete iteration (the stream pool's hard stop and stage p07's solve3D rely on that). The typed entry points and the builder's spproj_src option are deleted.

    The items¶

    Phase 1: the 2D structure aligned with 3D¶

    1. Restoration and convergence out of the 2D matcher. The matcher keeps everything through the orientation writes, the worker's cavger_write_contribution and cavger_kill, and qsys_declare_part_finished; in shared memory it returns with the sums in the class averager. New strategy routines: the shared-memory restoration (the matcher's present restoration lines, unchanged in order) and one convergence routine both modes call (check_conv2D, minits, maxits, coverage, the verdict, the progress file). The matcher's converged argument and the dead refine2D_ctrl%display go. Keep the order that makes results identical:
    2. convergence runs before the shared-memory strategy restores update_frac (check_conv2D reads params%l_update_frac);
    3. the carry-over flag (l_frac) is returned by the matcher (it is computed inside the matcher's set-up, and the shared-memory strategy may switch fractional update off before the matcher runs);
    4. convergence runs after cavger_gen2Dclassdoc, which writes each particle's res that check_conv2D averages;
    5. check_conv2D changes params%trs and l_doshift: shared memory applies them in the next iteration, distributed through the job description from iteration 4; keep both;
    6. a fresh convergence object per iteration in shared memory, as today;
    7. cavger_new stays in the matcher (reference preparation needs it);
    8. shared memory is not routed through part files and cavgassemble: its particle field on disk is stale during the run.
    9. refine2D public. A new_refine2D descriptor in simple_ui_refine2D.f90 (category refine2d, the visibility refine3D has, required keys only projfile and mskdiam, since the private command of the same name is checked against the public required keys); case('refine2D') in simple_exec_refine2D.f90 routed to commander_refine2D; the private refine2D stays the worker (the memory estimator keys on it); scripts/default_audit.py traces set_refine2d_defaults; a registration check in simple_ui_visibility_tester.f90; the UI JSON validator passes. The GUI accepts class selection only from solve2D (nice/): report it, do not edit.
    10. solve2D_policy.md describes the new ownership (matcher, strategy, public program).

    Phase 2: the bodies out of the commanders (3D, pure moves)¶

    1. Volume assembly (run_volassemble, restore_state_from_parts, filter_pcg_nonuniform_maps) moves into a new strategy module, simple_volassemble_strategy.f90, beside simple_rec3D_pcg_strategy.f90. The commander keeps building params and the builder and calls it; the strategy modules stop importing the commander module. Identical.
    2. prob_align, prob_align_neigh and the sigma commit move the same way: the two alignment bodies into a new simple_prob_align_strategy.f90, the commit into simple_strategy_sigma2.f90. Identical.
    3. Volume names as outputs. Assembly returns the names of the volumes it wrote instead of writing params%vols, vols_even, vols_odd, so that a caller's params never points at a state left without a map. Identical.

    Phase 3: the 3D master owns its project¶

    1. The master's own builder replaces the kept builder. Build the general and 3D search toolboxes once on build; each iteration remake the volumes (a builder method, not hand-written in the strategy), rebuild the search toolbox, set the band and materialise the model on build, as the shared-memory path does. The full read after the model becomes a read of the particle segment while assembly still writes the file. Check projinfo and out in the dumps.
    2. prob_align and prob_align_neigh on the master's builder. Sampling happens in place; the body sets the thread count it needs (the workers' nthr, as its command line said) and the master restores its own after. No reseed (ruling): later draws change.
    3. The sigma commit on the master's builder, with explicit which_iter and thread count, the same way.
    4. The two execute_from_project entry points go. The distributed strategy calls the bodies directly since items 8 and 9; shared memory stays on the commanders' execute(cline). Identical to item 9's build.
