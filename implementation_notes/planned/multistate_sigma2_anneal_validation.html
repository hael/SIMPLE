    Multi-state workflows under scoring-noise annealing: validation on the SNR 0.05 benchmark¶

    Status, 2026-11-20: planned, for the autonomous run ms_anneal on dell2. Base: f9fd7ca21 (the commit that adds this plan sits on top; the launch copies the checkout at that commit and Phase 0 records the base it got). Supersedes: none. Depends on: 5709265cb (sigma2_anneal=yes the default of solve3D, refine3D_auto, refine3D_local and refine3D_states; validated: by the multistate_workflows entry once, on 3,000 particles at SNR 1; never on the benchmark the multi-state work is judged on).

    1. Why¶

    Every multi-state control so far scored the particles against measured noise. The de novo runs that set the standing success criterion (multistate_ab_initio_recovery.md, ruling 12) ran on 1c12bb4eb and separated the three states of the SNR 0.05 benchmark F05 in 4 of 5 runs (final accuracy 0.996, 0.863 partial, 0.969, 0.969, 0.969); the validation of 4282d58a3 (2026-11-15) separated its one finished run (0.927 at iteration 82, recall 0.89 / 0.97 / 0.79). In all of them solve3D ran without annealing: its default was no until 5709265cb (2026-11-20), and the log of the 2026-11-15 run has no SIGMA2 ANNEAL line. Since then the multi-state five-stage schedule scores stage 1 (shc, 30 A) from the white ceiling toward the smoothed bootstrap (weight -1 to -0.5), stage 2 (shc, 24 A) on to the bootstrap (-0.5 to 0), stage 3 (the first prob stage, where the states are gathered: in run 1 of 2026-11-11 the largest assembly went from 0.69 to 0.95 during it) from the bootstrap to measured noise (0 to 1), and stages 4-5 at measured noise (set_refine3D_sigma2_schedule, simple_solve3D_controller.f90, with NSTAGES_INDEPENDENT = 5, PROB_REFINE_STAGE = 3, STICKY_LAST_STAGE = 4). refine3D_states, the route Hans and Cyril use on real data (consensus: single-state solve3D, then refine3D_states), now smooths the spectra it starts from, scores its whole frequency march at that anchor and ramps to measured noise over the march's last three planned iterations (run_frequency_march, FREQUENCY_BLOCK_NITS = 3). Whether the states still separate under the new scoring is unmeasured. This run measures it, on the same commit, with and without the switch, and only if annealing loses states does it change code, confined to nstates > 1.

    The 23 commits between 4282d58a3 and the base also touch solve3D's path (the sticky subset of 8363af240, the equal class quotas of 11f832a8e, the removal of the 3D in-plane posterior insertion in fd9af0add, nsample_ramp given up in 6668fb842, the PorF low-pass fix a4881e6c4). 8363af240 says multi-state is unchanged by the sticky subset. The arm without annealing is therefore also the regression check of the base for multi-state since 4282d58a3.

    2. Contract¶

    • A validation on a frozen export of the base. Phases 0-3 change no production code. Phase 1 changes test code only: the multistate_workflows routes that run solve3D or refine3D_states pass sigma2_anneal= on when the test is given it, and test=profile forwards the key as it forwards suite=. With the key absent the routes run exactly as before (the entry's command lines are unchanged: the off-state invariant of the test change).
    • Phase 4 runs only if the verdict of decision 5 or 7 names a loss. A candidate there changes the schedule or the default for nstates > 1 only; nstates = 1 stays byte-identical at one thread (simulated_workflow_6vxx identity, base export against the tree); no new parameter; no floor, tolerance or timeout of an existing test relaxed; no edit of the anchor smoothing, the blend, or the 2D schedule.
    • The two arms differ in one key on the command line: arm Y runs the default (sigma2_anneal=yes), arm N adds sigma2_anneal=no. With no, solve3D's stages run refine3D without the key (refine3D's own default is no), and refine3D_states prepares no anchor and sets no weights: arm N is the scoring every earlier control had.

    3. Decisions and rulings¶

    1. (2026-11-20, Hans) Pick the multi-state controls on dell2 up again now that sigma2_anneal=yes is the default of solve3D and the refine3D controllers, as an autonomous testing run.
    2. (2026-11-20, the plan) Design: a same-commit A/B. Arm Y, the default; arm N, sigma2_anneal=no on the command line; nothing else differs. SIMPLE_SEED stays unset for every benchmark run (each has its own random start), so the arms are two profiles, not pairs.
    3. (standing: multistate_ab_initio_recovery.md ruling 12 and section 4) The judge is the SNR 0.05 benchmark F05 on dell2: simple_exec prg=solve3D pgrp=c1 mskdiam=300 nstates=3 nparts=2 nthr=8 print_states=yes projfile=P2_05.simple, from a fresh copy of the 2D solution P2_05 per run. A run's result is its last states_iter*.txt (the final assignment at prob_beta 1), scored by acc3.py --truth labels_f05.txt: separated when accuracy is at least 0.90 and every true state's recall at least 0.75; partial when accuracy is at least 0.75 or exactly two states are recovered; failed otherwise (origin: the recovery plan, section 4; measured there: the separated runs sit at 0.969-0.996, the partial one at 0.863). The stopping rule stays: a run whose stage-4 accuracy is below 0.60 is stopped and counts as failed (measured: separated runs are at 0.965 or more after stage 4, the partial one at 0.765).
    4. (2026-11-20, the plan) Three F05 de novo runs per arm, one at a time, in the order Y N Y N Y N, so that whatever drifts on the machine touches both arms alike. About 6-7.5 h each (measured, nparts=2 nthr=8, load about 16).
    5. (2026-11-20, the plan; frozen before Phase 2) The reading of Phase 2, written before any run:
    6. Y separates at least 2 of 3: the standing criterion holds under the default. No code change. The difference between the arms is reported as a lead (three runs per arm cannot measure a modest shift: at a per-run separation probability of 0.8, 2 of 3 or better comes up 9 times in 10).
    7. Y separates at most 1 of 3 and N at least 2 of 3: annealing loses states in multi-state de novo. Phase 4 runs candidate A1, then A2, each judged by the same rule.
    8. Both arms separate at most 1 of 3: the base itself no longer meets the criterion (at 0.8 per run this happens by chance about once in a hundred). STOP with the evidence: locating which of the 23 commits since 4282d58a3 did it is not in this plan.
    9. Y separates 3 of 3 and N at most 1 of 3: annealing helps. No code change; reported.
    10. (2026-11-20, the plan; frozen before Phase 1) The cheap fixtures, as profiles of 20 seeds per arm (test=profile target=multistate_workflows suite=<route> nseeds=20 ncunits=16, two executions at a time at eight threads each): the shc route (de novo solve3D on 3,000 particles; last profile 15 of 20 resolved every state, 2026-11-05, dell2; floor 6 of 20), the states route (refine3D_states from the true poses and the consensus map; 20 of 20 in its profile) and the consensus route (single-state solve3D then refine3D_states; 40 of 40 in October, borderline on 2026-11-04: 1 of 3 eight-thread runs lost a state). Per route the count of runs that resolve every true state and the medians of accuracy, adjusted Rand index and the smallest recall are recorded for both arms. A difference of 5 or more runs of 20 between the arms is a finding; less is a lead (guessed from the binomial spread: at 15 of 20 the standard deviation is 1.9 runs, so 5 is about 2.6 of them). The shc floor of 6 of 20 is a gate for arm Y (it is the production default); below it, Phase 4 candidate A2 is tried whatever Phase 2 says. The labels route runs plain refine3D, whose default is no: it is not profiled.
    11. (2026-11-20, the plan; frozen before Phase 3) refine3D_states on F05, the real-data route on the benchmark, has never been measured.     6. Acceptance¶

    Numbers and their origins (all frozen at the date of this plan):

    • Separated: accuracy at least 0.90 and every recall at least 0.75; partial: accuracy at least 0.75 or exactly two states recovered (measured: the recovery plan's runs; acc3.py defaults).
    • Standing criterion: at least 2 of 3 F05 de novo runs separated (ruling 12 of the recovery plan).
    • Stopping rule: stage-4 accuracy below 0.60 (measured: 0.765-0.995 after stage 4 in the five runs of 2026-11-11/13).
    • Profile margin: 5 of 20 runs (guessed, binomial spread, decision 6). shc floor: 6 of 20 (standing, test_environment_policy.md).
    • refine3D_states on F05: 10 h wall per run (guessed budget, decision 7).
    • Reported, not gated: the final maps docked on the truth maps in both hands (dock_eval.sh, keep/runs/<run>/dock_eval.txt), the accuracy at each stage end and each iteration (metrics.txt), the SIGMA2 ANNEAL readout of every iteration of arm Y (weight, beta, band, the mean log ratio of measured to anchor noise) tabulated per stage, the wall time and load per run. Hans reads the maps.
    • No identity case in Phases 0-3 (no production code changes). Phase 4's identity case: simulated_workflow_6vxx at one thread with the test environment's seed, base export against the tree, compared with test=identity target=simulated_workflow_6vxx dir1= dir2= (about 13 min per build on dell2); no exclusions.

    7. Common rules and stop conditions¶

    • No new parameter. Experimental variants, if any, are patches on git archive exports under scratch/keep/variants/, never keys.
    • No floor, tolerance, timeout or assertion of an existing test is relaxed. A floor never comes from the first run of the code being accepted.
    • Fix as you go: a defect met on the way is fixed in the run only if it sits in a file of the table; otherwise it is recorded with its evidence and the run goes on. A file table row is added before any edit outside the table.
    • Every benchmark run keeps its labels, log, statistics snapshots, metrics, docking and final maps under scratch/keep/runs/<run>/ with one line in scratch/keep/runs/summary.tsv (run, arm, build, wall, accuracy, recall per state, ARI, populations, per-stage accuracy, verdict, notes); the rest of the run directory is deleted once that line is written. SIMPLE_SEED is unset for every benchmark run.
    • Thread and disk policy: decision 10; the engine's disk floor (DISK_MIN_GB).

    Stops (written up as a question for Hans with the evidence, never worked around):

    • both arms fail the standing criterion (decision 5, third case);
    • the F05 inputs or the truth are missing or do not verify (Phase 0);
    • the export does not build or the fast gate fails on the base;
    • a candidate cannot keep nstates = 1 identical, or would need a new key;
    • the machine cannot run what a phase needs (disk, a job the budget cannot hold).

    Gates no ruling may waive: nstates = 1 identity for a kept change; the shc floor of 6 of 20 for a kept change; the fast gate; no relaxed floor.
