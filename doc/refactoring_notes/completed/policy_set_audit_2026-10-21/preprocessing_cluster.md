### 0.3 One pattern or several? Several (four), with inconsistencies

Patterns: (A) mic-segment part documents merged by `merge_algndocs` (motion_correct, ctf_estimate, pick, gen_pspecs, preprocess); (B) full part projects assembled by hand by the master (extract, reextract, refine_motion_model); (C) job project written in place by the worker (stream=yes preprocess L337, extract L458); (D) stage-owned global project (stream). Inconsistencies:

1. [M] Two worker output formats for the same job. A is range-checked by `merge_algndocs` (coverage and overlap errors, simple_sp_project_core.f90 L586/L608/L636/L638). B has only count checks (extract L659 `cnt /= nmics_tot`, reextract L605 `nstks /= nmics`) and no coverage check of the ranges.
2. [M] Three copies of the "assemble mic/stk/ptcl2D/ptcl3D from part projects" code: extract L643-717, reextract L585-640, refine_motion_model L565-625; and three copies of the worker boilerplate "read non-data segments, set projname/projfile, new segments, transfer_ori, write" (extract L226-241, reextract L410-436, refine_motion_model L359-385).
3. [M] extract copies particle fields one by one (boxcoords, dfx, dfy, angast, phshift, ogid, gid; L682-711, four near-identical `isthere`/`set` blocks each for ptcl2D and ptcl3D) while reextract and refine_motion_model use `transfer_ori` of the whole row (reextract L634-635). A new particle field set by the extract worker is dropped silently by the master.
4. [M] extract's master writes the full project before the workers (L588, only to wipe stk/ptcl/cls/out on disk) and again after (L719); reextract wipes in memory and writes once. `layering_and_project_ownership_policy.md` 5.4 ("one write per iteration") is not met by extract; undocumented why the wipe must reach the disk before the workers run (they read only mic/non-data segments).
5. [M] In A the master reads the project twice (a `read_segment` to count, kill, then a full `read` just to give `merge_algndocs` the project name and a segment buffer): motion L281+L320, ctf L263+L295, pick L500+L545, gen_pspecs L230+L259, preprocess L394+L425. Layering 5.5 asks for "that segment, not the project".
6. [M] Workers in A read the whole project (`spproj%read`, incl. stk/ptcl segments of a post-extraction project) to update a few mic rows (motion L176, ctf L164, pick L436, gen_pspecs L156, preprocess L207); extract and reextract read segments selectively.
7. [M] `nparts` larger than the number of items: motion_correct L286-288 and preprocess L400 stop with an error; ctf_estimate L273-276, gen_pspecs L236-241, pick L508, extract L558, reextract L523 clamp.
8. [M] The same 5-line gain block (`flip_gain`, then `params%flipgain='no'` and `cline flipgain='no'`) is copied in motion_correct_strategy L157-161 and L291-295 and preprocess_strategy L164-168 and L406-410; the stream stage does the equivalent differently (simple_stream_stage_preprocess.f90 L456-487, L634).
9. [M] There is no shared-memory path. `nparts` is a required UI key of these programs (simple_ui_params_common.f90 L489-491, `.true.` = required; added as UI_COMP in simple_ui_preproc.f90 L120/L160/L237/L310/L432/L524/L567), and the "inmem" strategies refuse to run without `fromp`/`top` (motion L206-210, ctf L174-178, pick L429-433, preprocess L243-248), so `nparts=1` is a master with one worker. The factory messages and file headers still say "SHARED-MEMORY / WORKER". `gen_pspecs_and_thumbs` keeps a non-worker branch (`fromto=[1,nintgs]`, L172) that writes `outfile.simple`, which nothing merges (L190): unreachable and wrong if reached. The `stream` branches in ctf_estimate (L170-173) and pick (L426-428) have no caller I could find (only `preprocess` and `extract` are launched with stream=yes).
10. [M] pick's master runs `make_pickrefs_impl` in its own process (L536), which calls `params%new` a second time (L213) and runs a whole commander (`commander_cluster_cavgs`, L228-236), handing over by file (`cluster_cavgs_from_stack.simple`, L236-237). Layering 4 allows commander-calls-commander only for controllers and demands `mkdir=no` and thread restoration; `params%new` reseeds the generator and resets threads in the master.
11. [L] `exec_pick_extract` (simple_commanders_pick.f90 L111-238, a commander) repeats the pick strategy's per-mic loop and then runs `commander_extract` with stream=yes; it writes the job project with `write_segment_inside` (L211/L231). A second copy of the pick loop (pick inmem L441-456).
12. [L] `ori%get_ctfvars` is used for the fit (ctf_estimate L208), extraction (extract L351, reextract L257) and `get_micparams` (motion L221, preprocess L271/L286); `sp_project%get_ctfparams` is used for particles. See microscope policy finding 5.

Proposal (where the rule belongs): add a section "Preprocessing steps" to `layering_and_project_ownership_policy.md` (or a new `preprocessing_policy.md`): (i) `nparts` is required, the master is the only process that writes the project, a worker writes one part file; (ii) part files are mic-segment documents merged with `merge_algndocs` for steps that only change mic rows, and ONE shared "assemble part projects" routine for steps that create stacks and particles (extract, reextract, refine_motion_model); (iii) the master reads `projinfo` plus the segments it needs; (iv) the stream job project is the one documented exception where a worker updates its own job file; (v) a domain object (`segdiam_bin_picker`) does not write the caller's project. Add the deviations above to section 8 of that policy.
