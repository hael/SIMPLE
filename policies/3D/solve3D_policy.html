    Solve3D Policy¶

    This document records the current policy for solve3D, the staged particle-based de novo map determination workflow: it couples ab initio 3D reconstruction from random orientations with initial 3D refinement of the resulting map in one stage schedule. solve2D is its 2D equivalent. The programs were called abinitio3D and abinitio2D before 2026-10-03 (release 4 keeps no aliases for the old names). The base refine3D contracts are in refine3D_policy.md; this document describes how solve3D configures and chains those stages.

    Multi-state matcher and reconstruction lifetimes follow separate_alignment_and_reconstruction_for_multistate_peak_mem_reduction.md.

    1. Scope¶

    solve3D determines 3D maps de novo from particles by preparing starting orientations/states, marching through staged refine3D runs (global-search ab initio reconstruction stages, then local-search initial refinement stages), optionally performing symmetry-axis search, and reconstructing final original-sampling maps.

    It owns stage scheduling. It does not own a separate particle matcher or volume assembly implementation.

    2. Defaults¶

    solve3D sets:

    • objfun=euclid
    • bfac=0

    When unset, it supplies:

    • mkdir=yes
    • overlap=0.95
    • prob_athres=10
    • center=no
    • cenlp from the solve3D controller default
    • oritype=ptcl3D
    • pgrp=c1
    • pgrp_start=c1
    • filt_mode=nonuniform
    • automsk=no
    • gauref=yes
    • balance=class (also with input volumes, which bring random classes and no class averages, cavg being rejected there; none for a project without a 2D solution)

    For a multi-state run (nstates > 1), it also supplies conservative inspection defaults when the user has not overridden them:

    • nstages=5
    • lpstop=6.0 A

    The public filt_mode values are none, nonuniform, and nonuniform_lpset. Automatic low-pass modes uniform and fsc are rejected for solve3D.

    3. Stage Controller¶

    The stage controller in simple_solve3D_controller.f90 emits a concrete refine3D command line for each stage. The full particle workflow has eight stages. Independent multi-state startup defaults to five stages, so it stops after its prob stages 3-5, before the first prob_neigh stage (6); stage 5 is also its first NU-filtered stage.

    Stage policy includes:

    • stage-specific nspace and maxits
    • cropped box and sampling from the low-pass plan
    • stage 1 starts with nspace=500; stages 2 through 4 use nspace=1000
    • every stage gets its low-pass and crop information independently from the size/input schedule
    • staged search by state count:
    • single-state particle runs use prob_neigh with prob_neigh_mode=shc in stages 1-2, middle prob, and late prob_neigh; under fractional updates the shc stages refine one sticky subset: stage 1 draws it at its first iteration (sticky_sampling=yes) and stage 2 keeps it (sticky_sampling=keep; a run that starts at stage 2 draws its own), because the shc neighbourhood search scans a never-searched particle in full and a fresh draw every iteration would make these stages a sequence of full scans; from stage 3 the sample is redrawn every iteration and trailing reconstruction blends the maps (TRAILREC_STAGE_SINGLE, until 2026-11-11 stage 5), so free sampling and trailing start together, as in solve2D; multi-state runs trail from stage 8 (TRAILREC_STAGE_MULTI)
    • multi-state particle runs use direct shc in stages 1-2, prob in stages 3-5, and prob_neigh with prob_neigh_mode=state from stage 6 (PROB_NEIGH_REFINE_STAGE, the single-state switch), so the default five-stage multi-state run uses no prob_neigh; the class-average route switches at the same stage (section 6)
    • the tempering of the draws is not a user input: every stage searches at prob_beta (the parameter's default, the stage command does not carry the key) and the last stage anneals to prob_beta_end=1, which the controller sets (prob_beta_ini, the stages 1-2 override, was removed 2026-10-29); in a multi-state run the same factor tempers the state, drawn with the direction, and the tail starts when no populated state gains (section 6)
    • the multi-state direction cap: with nstates > 1 no stage exceeds 2,500 directions, so stages 7 and 8 (5,000 in single state) run at 2,500
    • the multi-state stage-2 exit: stage 2 of a multi-state particle run (shc) also ends once the search scans more than 95% of the search space on average, whatever the state overlap (section 6)
    • nspace_sub for prob_neigh
    • staged point-group policy between pgrp_start and pgrp
    • staged translation limits
    • staged ML regularization
    • staged fractional update with a fixed nsample target while nsample/active_particles <= 0.9
    • fractional-update selection over the sampling units of balance: cavg by default (groups of similar class averages, then their classes), class (one unit per selected class) or none (global lowest updatecnt tiers)
    • stochastic sampling start by state count
    • early Gaussian reference filtering
    • optional trailing reconstruction by stage and state count
    • staged NU filtering from NU_FILTER_STAGE
    • single-state gold-standard matching from stage 6 by default (gold_std_stage overrides the start)
    • spherical support throughout, with automsk=no and envfsc=no
    • a requested PCG backend (rec_backend=pcg) from stage 6 (PCG_START_STAGE), gridding before; changing gold_std_stage does not retime this backend switch
    • an explicitly requested PCG order prior (pcg_order=yes) from the same stage (PCG_START_STAGE), on the NU evidence and labels of the previous iteration (section 9)

    The downscaled particle cache is a 2D-only feature: solve3D rejects cache=yes, and each stage uses its own crop from the low-pass/downscaling ladder.

    The effective crop and its physically equivalent pixel size are shared by starting-volume generation, matcher reconstruction, stage-boundary reconstruction, symmetry-map commands, FSC diagnostics, low-pass snapshots, and project volume registration. This preserves box * smpd == box_crop * smpd_crop across every particle-to-volume handoff.

    Full-Sampling Switch¶

    solve3D now applies a global sampling override when:

    nsample / active_particles > 0.9

    In that regime, the staged controller forces full active-particle updates for each iteration by suppressing fractional controls (update_frac, nsample) in emitted child refine3D commands. This also disables trailing reconstruction for staged solve3D commands, and startup class-biased sampling setup is bypassed in favor of all-active sampling.

    Sampling units¶

    Every stage runs with the run's balance (default class). Below the full-sampling switch, solve3D writes the class sampling file clssmp.bin once at startup: one unit per selected 2D class, and under cavg each unit's group among nclust (default 20) groups of similar class averages, formed by average linkage on their aligned correlation between 30 and 6 A, a group with fewer than 2.5% of the particles merged into its nearest group, so a preferred view spread over many classes no longer dominates the sample and an odd class does not become a group of its own. Every fractional update shares its target over the groups in proportion to the square root of their populations, then over the classes of a group the same way, each capped at its population, then lowest updatecnt first inside a class, drawn from the whole class: no per-particle 2D score enters the draw. Under class every class is its own group, so a rare view is sampled more often than its population alone would give, without one small class taking a large part of every draw (equal shares did: on a small membrane protein with six one-class groups of odd class averages, cavg with equal shares drew 80% of every sample from 18% of the particles); under none the stages sample the global lowest updatecnt tiers, and the file holds class units only for the initial sample of the starting volumes. The groups are written as view_partitionNN_cavgs stacks with the table view_partition.txt. The units are formed once, before the first stage, and serve the whole run: the stages only read the file, and every stage command line carries balance and, for cavg, nclust. Before the first stage solve3D prints the unit table with the expected visits per particle over the planned stage iterations, the view imbalance corrected, and a warning on short coverage only; nothing is adjusted automatically. The sampler never uses 3D maps, poses or projection directions. The details are in doc/policies/importance_sampling_fractional_update_policy.md.

    The emitted child command line owns startit and which_iter for the current stage. refine3D then treats maxits as the run length for that stage.

    Without a 2D solution¶

    solve3D and solve3D_addon run on a project without a usable 2D solution (ptcl2D never searched, or no classes in cls2D, or no class FRCs registered, as in a project built from particles alone with per-particle labels) under balance=none only; class and cavg are refused with a message naming balance=none, as are cavg_ini and cavg_ini_ext. balance then defaults to none. The selection is unchanged: ptcl3D%state is reset from the ptcl2D state flags (set at import or by a selection). The 2D shifts are transferred when ptcl2D was searched and otherwise the shifts ptcl3D holds stay. No class sampling file is written; the initial greedy draw and every stage sample the global lowest updatecnt tiers (sample4update_cnt), as every balance=none stage does. The ladder is planned from input limits: lpstart/lpstop are taken from the command line and otherwise lpstart from mskdiam (mskdiam2lplimits) and lpstop is the ladder bound LPSTOP_BOUNDS(1), 4.5 A, as on the input-volume route; an add-on takes its ladder from the frozen run's manifest regardless. Input volumes on such a project no longer need the random classes the class default fabricates.

    Stage-start sigma bootstrap (ini3D routes)¶

    The cavg_ini and cavg_ini_ext routes enter the particle stages at a stage whose starting reconstruction is ML-regularized (objfun=euclid) before any refine3D iteration has estimated particle sigmas. calc_rec applies the single sigma2 bootstrap rule (simple_sigma2_bootstrap, doc/policies/3D/refine3D_policy.md section 5): for a euclid starting reconstruction it calls ensure_sigma2_for_iteration, which is a no-op when the project owns a compatible committed state and otherwise seeds canonical particle spectra from image power with calc_pspec. The starting reconstruction then runs as planned, and the stage's first euclid iteration replaces the seed with residual spectra in the next canonical transaction. When the final reconstruction at original sampling must rebuild its sigmas (section 9) it is one program call, bootstrap_rec3D, which owns the complete sequence: the same image-power seed, a euclid ML bootstrap map on it, one residual sigma pass (refine=sigma) against that map, canonical commit of the residual generation, and the shipped euclid ML reconstruction on it. Because the program takes any project with 3D orientations, it is also the standalone test for this stage (simple_exec prg=bootstrap_rec3D projfile=... pgrp=... mskdiam=... nparts=... nthr=... rec_backend=...), so failures in the final reconstruction can be reproduced in minutes rather than after a full run. Its bootstrap map is a gridding assembly that carries the last stage's filt_mode and automsk (the residual sigmas depend on the regularization of the reference they are scored against, so that reference is regularized like the last stage's matching references); the shipped map is classical (filt_mode=none, except that automsk=nu keeps the caller's NU filt_mode) and runs on the workflow's backend with the PCG cold-solve budget applied inside bootstrap_rec3D (2026-09-07). Whether the final reconstruction refreshes its sigmas at native sampling is decided by the registration-box rule: a registration box different from the native box forces refresh (2026-09-07). Solve3D drops any state registration inherited with its input project before the first stage, so every run seeds and owns its sigmas in its own directory.

    5. Initialization Modes¶

    solve3D supports these model-start routes:

    • random starting volumes
    • user-supplied input volumes
    • initialization from solve3D_cavgs inside the workflow through cavg_ini=yes
    • externally supplied class-average initialization through cavg_ini_ext=yes

    Volume input is allowed for single- and multi-state runs (one volume per state). It cannot be combined with class-average initialization or partitioned startup. User-supplied input volumes are assumed to be aligned to the target symmetry axis, so pgrp_start is set to pgrp and the particle workflow does not run symmetry-axis search on them.

    Input volumes are not assumed to share the particles' alignment provenance. Before the Euclidean stage ladder, this route calls the shared fixed-reference CC pose-initialization service. It first runs the normal native-grid particle-image sigma2 bootstrap, then performs one pass over at most 100,000 active particles at a common 15 A limit. In selected particle records, the pass replaces active matching shells with reference-conditioned residual sigma2, consolidates those residuals for the first Euclidean stage, and reconstructs a data-derived checkpoint. Particles outside the capped cohort retain their image-bootstrap partition records until later refinement updates them. The external maps remain fixed during the CC pass and are not blended into the checkpoint. The helper copies the planned stage command line but removes its explicit shift_sigma before the objfun=cc pose pass: the polar shift map is a Euclidean objective feature, and an explicit key is invalid under CC. The stage command line keeps shift_sigma for the subsequent Euclidean stages.

    Normal particle-based starts treat solve3D as the producer of new ptcl3D orientation and multi-state information. The workflow resets ptcl3D sampling, deletes previous 3D alignment while preserving shifts, transfers 2D shifts from ptcl2D, and initializes ptcl3D%state only from the 2D selection state: selected particles become state 1 and unselected particles become state 0. Fresh multi-state runs then randomize active particles into the requested 3D states with balanced uniform labels.

    Class-average initialization and external class-average initialization both skip the random-volume start. With cavg_ini=yes, the nested solve3D_cavgs run owns any pgrp_start to pgrp symmetry-axis search. When control returns to the particle workflow, pgrp_start is set to pgrp so the axis search is not repeated. The nested run has as many stages as the symmetry-search stage (solve3D_nstages_ini3D, four), so it ends with the axis search on the class averages whenever pgrp_start != pgrp (section 7). The particles then enter at that last class-average stage, stage 4, which runs its full budget (overlap 0.99, fracsrch 99) on the particles, whatever the point group (2026-10-17; they entered at stage 3 before). cavg_ini_ext=yes is the explicit exception to the fresh-start rule: it requires prior ptcl3D alignment, preserves the external orientation/state information needed by that route, assumes the input orientations are already symmetrized, and starts at stage 4, after the stages a run without an axis search keeps in pgrp_start. A prior solve3D_cavgs run with pgrp_start != pgrp and fewer than 4 stages, which would stop before its axis search, is refused by solve3D_cavgs. If nstates > 1, every requested prior ptcl3D state must exist and be populated.

    6. Multi-State Policy¶

    nstates alone selects the mode; solve3D has no multivol_mode input and refuses it on the command line. nstates=1 is the single-state run. nstates > 1 refines independent states from the start: every state has its own starting model and its own refinement. There is no docked mode (one consensus model up to a split stage, then states); it was removed on 2026-10-06. To split a finished single-state solution into states, run refine3D_states on its project, where flex PCA initializes the states.

    A multi-state run preserves the staged point-group policy between pgrp_start and pgrp. When pgrp_start != pgrp, the symmetry-search stage searches the symmetry axis independently for each state, matching the state-wise behavior used by direct solve3D_cavgs runs. This applies to fresh particle starts only; cavg_ini=yes, cavg_ini_ext=yes, and user-supplied input volumes are already in the target symmetry frame before the parent particle workflow resumes. The multi-state run is intended for severe heterogeneity where early inspection is more valuable than committing to a longer refinement immediately. Its particle stages 1 and 2 use direct refine=shc rather than the probabilistic-neighborhood startup of the single-state run; stages 3 to 5 use refine=prob, and refine=prob_neigh with prob_neigh_mode=state starts at stage 6, the stage single-state runs switch at (PROB_NEIGH_REFINE_STAGE), so the default five-stage run never reaches it. From 2026-10-16 to 2026-10-21 stage 5 ran prob_neigh, because the dense prob table over 2,500 directions of every state was the most expensive stage of a multi-state run. That was a mistake (ruling of 2026-10-21): stage 5 is where a multi-state run makes its final labels, and there the neighbourhood search lost states. On a simulated two-state set the builds with prob_neigh at stage 5 drained a state during it or split the states too slowly, while the build of 2026-10-15 with prob at stage 5 completed the separation there (accuracy 0.86 to 0.97). The class-average route (solve3D_cavgs with nstates > 1) shares this mode policy and switches at the same stage; its early stages keep their own class-average search schedule. The cap of 2,500 directions (NSPACE_MULTI_MAX) also limits every multi-state stage to 2,500 directions: stages 7 and 8, which run 5,000 directions in single state, run 2,500 when a user extends a multi-state run to them.

    Stage 2 of a multi-state particle run ends by the multi-state convergence rule (every state's orientation overlap above 0.96 and the mean percentage of the search space scanned above fracsrch) or, since the rulings of 2026-10-15, once shc scans more than 95% of the search space on average, whatever the state overlap. The measure is the mean over the sampled particles of the per-particle frac, which the log prints as "% SEARCH SPACE SCANNED". The controller sets fracsrch=95 together with the internal key scan_exit=yes on stage 2's refine3D command line (an internal parameter with no interface entry); the convergence check then ends the stage on the scan alone. Without the key, stage 1, every later stage and every other user of the multi-state rule keep the rule as it was. An shc search scans more of the references the longer the states settle, so a stage that kept running until the overlap converged spent most of its time scanning nearly the whole space. A solve3D_addon pass keeps its own early stopping and does not set the key.

    No stage of a multi-state run is skipped or cut short by a resolution rule (ruling of 2026-10-21): the mid-stage resolution exit (and, until 2026-11-12, the stage omission) of section 4 apply to single-state runs only (solve3D_stage_skipping in the stage controller), so every multi-state stage runs until its own convergence rule or its MAXITS. Both rules read the best state's FSC=0.5 resolution. At the start of a multi-state run every state holds a mixture of nearly the same structure, so the best state resolves early, and the rules removed exactly the prob stages in which the states split. On a simulated two-state set (30,000 particles, two RNA polymerase conformations) the build of 2026-10-20 omitted stage 3, ended stage 4 after 3 of its 15 iterations and lost the second state in stage 5 (accuracy 0.57), while the build of 2026-10-15, which ran stages 3 and 4 in full, separated the states during stage 4 (accuracy 0.97). The stage-boundary FSC=0.5 advance of a stage's limit still applies.

    Unless the user overrides them, the commander sets nstages=5 and lpstop=6.0 A. Stage 5 is NU-filtered (since 2026-10-18, section 8) but runs no multi-state trailing reconstruction or staged automasking. After stage 5, the workflow still runs the final original-sampling reconstruction so the run produces inspectable rec_final_stateNN volumes. Every stage samples each unit's quota from the whole class, lowest update count first; no per-particle 2D score enters the draw (section 3, sampling units; single state took each class's best 2D scores until 2026-11-11). A greedy sample never searches the particles outside it, so a minority state would keep its start labels. The outer particle target remains the fixed nsample-derived update fraction while nsample/active_particles <= 0.9; above that threshold the workflow runs full active-particle updates each stage.

    The state assignment (2026-11-05; design and validation in doc/implementation_notes/completed/multistate_posterior_state_draw.md). In the prob stages a particle's state is part of the posterior draw: one draw from its tempered posterior over every active state's block of its row, at the stage's prob_beta, so the state and the direction come from the same draw (refine3D policy, "Dense-table assignment"). From stage 6, when a run is extended to it, the neighbourhood table draws the same way over its pooled candidates. Before, the state was the particle's closest reference over all states and the direction one draw within it. The labels stay hard: one state per particle per iteration, one half-map, the weighted insertion's extras from the drawn state alone. The table's refined-reference budget is split over the states' blocks within the per-particle budget projs_ns. So every state gets the same number of shift-refinement attempts, and no block is left with stored-shift losses only because another state leads. Stages 1-2 keep their hill climb over states and directions. The annealing tail of the last stage starts when no populated state gained on the previous iteration (refine3D policy, the annealing tail), not when the best state alone stalls.

    Every probabilistic iteration of a multi-state run logs the state readout beside PROB_TAB_ASSIGN, and the iteration's statistics record holds it (STATE_NEFF_DRAW, STATE_NEFF_PHYS, STATE_MODE_FRAC, STATE_MASS_UNREFINEDnn): - PROB_TAB_STATE_DRAW: the effective number of states (exp(entropy) of the state marginal) at the draw's factor and at 1, the share of draws at the state mode, and the mean largest state posterior; - PROB_TAB_STATE_MASS per state: the share of the block's tempered mass on entries the fill did not refine.

    Read beside the populations and STATE OVERLAP, a state n_eff near the number of states while the labels stay at chance says the state draw is too hot, unless the n_eff at 1 is broad as well: then maps that cannot yet tell the states apart give the same picture. Near 1 from the first iterations is the lock-on signature of the retired closest-state rule. A large unrefined share says the marginal rests on stored-shift losses.

    On the simulated beta-galactosidase states of multistate_workflows, the shc route resolved every state in 15 of 20 seeds and the labels route (true poses, random labels) in 13 of 20 (2026-11-05). On 20,000 particles of Afan's simulated three-state Ribosembly benchmark, three de novo runs did not separate the states: accuracy, the share of particles in the found state matched to their true one, was 0.42-0.59. There stage 3 showed a broad state posterior (2.2-2.7 effective states at 0.3, 1.3-1.7 at 1) with accuracy near chance and a quarter to over half of each block's mass on unrefined entries (2026-11-06, the plan's Phase 4).

    Prior-orientation multi-state refinement belongs in refine3D_states, not in particle-based solve3D startup.

    7. Symmetry¶

    pgrp_start and pgrp must be compatible symmetry groups. If the workflow raises symmetry, the start group must be a subgroup of the target group. If it lowers symmetry, the target must be a subgroup of the start group and symmetry randomization may be applied.

    The axis is searched after stage 4 (SYMSRCH_STAGE; after stage 3 until 2026-10-17, when the stage-3 map was too poor and the search failed too often). The stages through it reconstruct in pgrp_start. The symmetry-search stage runs its full iteration budget (minits=maxits, overlap 0.99, fracsrch 99) and defers its canonical sigma2 commit to after the symmetric reconstruction. A run that searches no axis (pgrp_start = pgrp: every c1 run and the input-volume, cavg_ini, cavg_ini_ext and add-on routes) ends that block at stage 3 (NOSYMSRCH_STAGE) as before, so its stage 4 early-stops (overlap 0.95, fracsrch 90) and its entry stage is unchanged, except that the particle stages of a cavg_ini run enter at stage 4 and run it to its full budget (section 5). solve3D_symsrch_stage returns the block's last stage for either case; the final-reconstruction rule (section 9) and the solve3D_chunks refusal follow it.

    At the symmetry-search stage, symmetry-axis search is state-local for multi-state runs. Each active state determines its own axis from its current map and applies that transform only to orientations assigned to that state. The alignment changes the particle frame and the point group, so every trailing chain built before it (gridding and PCG, with its provenance records) is deleted right after the axis search. The following full symmetric reconstruction seeds a new chain through trail_seed only when the stage it feeds trails (solve3D_stage_trails, the same rule that emits trail_rec); otherwise no chain remains.

    The axis search scores the Fourier shells between its high-pass and its low-pass. The low-pass is the planned limit of the symmetry-search stage, at least 12 Å; the high-pass is the run's hp (by default half the box), but never finer than that low-pass, so the band always holds at least the shell of the low-pass. A stage limit as coarse as half the box (planned from the class Fourier ring correlations of very few particles) once left the band empty, and the search stopped on undefined scores; the polar volume correlator now refuses a band without a shell above the origin (2026-10-15).

    After symmetry handling, the selected maps are injected back into the staged refine3D command line and reference-section files are invalidated.

    8. Filtering and Gold-Standard Matching¶

    Staged solve3D uses the same static-ladder NU competition as refine3D_auto. Its objective and reconstruction support remain spherical (mskdiam). The workflow forces automsk=no and envfsc=no in every stage and in the final reconstruction; it generates no density or NU-evidence envelope for masking. The UI offers no envelope controls for this workflow.

    Before gold-standard refinement starts, NU-enabled stages use nonuniform_lpset, a merged registration reference and the scheduled lp. The FSC=0.5 stage-boundary advance in section 4 is preserved. NU matching updates retain their existing bandwidth policy, with no added ceiling at the planned stage limit; an explicit user lpstop is still respected.

    Particle runs with nstates=1 use half-specific references from stage 6 by default. gold_std_stage=0 selects this default; a positive value overrides the first gold-standard stage. Negative values are rejected. A value beyond nstages defers the switch past this run. The former gold_standard=yes|no flag is removed. Every stage runs; the configured start switches to half-specific matching (or the entry stage when starting beyond it). The controller switches either NU mode to plain nonuniform, deletes scheduled lp, and removes the stage-derived ceiling. NU chooses the matching band, subject to crop Nyquist and explicit user lpstop; without NU, the existing half-map FSC policy chooses it. An explicit lp applies before the switch; gold-standard stages delete it. Use lpstop for a ceiling that survives the switch.

    Fractional sampling, trailing accumulators and early stopping continue under their existing rules. The transition adds no full alignment or reconstruction pass and does not reset the trailing chain. The particle even/odd partition is preserved. Frequencies already used with shared references retain their initialization history; the switch does not retroactively validate the earlier FSCs.

    An explicit positive gold_std_stage requires a single state; an extended multi-state schedule keeps LP-set matching under the default policy. The class-average route never switches. The manifest records the stage override, and add-on runs replay it as part of the frozen solution's policy. Their initial registration pass retains its existing planned-band matching; the stage proper follows the recorded policy. Manifest version 3 distinguishes this default-on policy from earlier manifests; version 2 manifests require a new base run rather than silently changing their matching policy on replay.

    NU filtering starts at NU_FILTER_STAGE = 5 (6 until 2026-10-18), overridable from the command line by nu_stage for testing (0 = the built-in value; 5 is the earliest accepted). NU filtering needs an alignment good enough for its local-resolution estimate: below that the estimate is meaningless, the filtered reference reinforces the bad alignment rather than correcting it, and the run goes into a hole. nu_stage 3 and 4 were tried on PfCRT and streptavidin and did not work. Stage 5 is one stage earlier than the prob -> prob_neigh switch at PROB_NEIGH_REFINE_STAGE. The two were the same stage before, so a reference becoming NU-filtered and a global search becoming a neighbourhood search arrived together and could not be attributed separately. Stage 5 also had capacity to spare on the PfCRT reference: resolution flat at 9.703 A from its third of twelve iterations, with only cFAR still moving (0.56-0.68). l_state_continue_mode already enabled NU from stage 5 (NU_FILTER_STAGE), so this is an exercised path rather than new ground.

    The default multi-state (nstates > 1) stage limit is stage 5 (NSTAGES_INDEPENDENT), so that final stage is now an NU stage; before 2026-10-18 default multi-state ran no NU-filtered stage at all. Applied to multi-state deliberately, for the quality the filtered reference is expected to give. TRAILREC_STAGE_MULTI remains stage 8, outside the default multi-state schedule. Users who extend nstages past stage 5 retain merged-reference NU matching and spherical support.

    Detailed NU behavior belongs to nonuniform filtering policy; detailed automasking behavior belongs to automasking_policy.md.

    9. Final Reconstruction¶

    solve3D runs a fresh original-sampling reconstruction from selected particles for full schedules, for every multi-state schedule, and for a single-state schedule stopped explicitly (nstages) at the symmetry-search stage or later (stage 3; stage 4 when the run searches an axis, section 7); the run manifest follows it, so such a run can be the frozen input of solve3D_addon, which then runs that stage. Single-state schedules stopped before it skip this final all-particle reconstruction. Before the final reconstruction, every active particle must carry an update; the final reconstruction leaves out rows without one, so a run whose sampling did not reach every particle would drop them. A single-state run assigns the rows no stage updated by a greedy missing-update pass (refine=greedy). A multi-state run instead gives every active particle its final label against the final maps at the physical posterior (2026-11-05, run_multistate_final_assignment). It is one refine3D iteration over all active particles from the last stage's command line (its band, crop and maps) with refine=prob, prob_beta=1 and no tail, update_frac=1, balance=none, trail_rec=no, volrec=no and topk=1. Because it samples every active particle, the final reconstruction uses labels of one provenance, each drawn at beta 1 against the last stage's maps; a particle that fits two states alike lands in one of them at random, which is the honest hard label. The coverage check after either pass (SOLVE3D ASSIGNMENT COVERAGE) must find no active particle that the run never updated. For multi-state runs it replaced the greedy missing-update pass. On the 20,000-particle benchmark subset it took 8-12.5 minutes and changed 1-3 % of the labels.

    The final reconstruction inherits only the scientific reconstruction policy it needs. It keeps envfsc=no and automsk=no, so the original-sampling half maps retain spherical support. It does not inherit staged search or reference-filter controls such as refine, lp or gauref. The final reconstruction runs with filt_mode=none on both backends.

    If the final stage used objfun=euclid and ml_reg=yes, final reconstruction uses the committed sigma2 store of the workflow's particles: one noise spectrum per even/odd half. A missing or incompatible store is rebuilt through the one rebuild entry before the regularized map is produced.

    On the PCG backend, a final ML-regularized stage uses the ordinary P_tau replay in bootstrap_rec3D; the Q_NU prior, its calibration pass and its controllers were removed on 2026-09-06. When pcg_order=yes, the staged controller forwards the order prior to every PCG stage from stage 6 and withholds it before; pcg_order_lambda is forwarded only when given, so an unset strength is chosen per state and iteration. The prior reads the previous iteration's _nu_evidence and _nu_locres maps of the same state and box, and the evidence map is written only under pcg_order=yes: the first iteration of stage 6, and the first at a new box, run without it (logged). The final reconstruction is prior-free. Design and evidence: doc/implementation_notes/planned/pcg_order_prior.md.

    The final reconstruction does not apply fractional-update sampling or trailing average blending. Final-map postprocessing is classical, even when staged refinement used NU-filtered references.

    10. Outputs¶

    Stage snapshots are written by simple_solve3D_utils.f90 with _stageNN suffixes and companion _lp diagnostics.

    Final outputs use the rec_final_stateNN naming convention and include raw and low-pass diagnostic volumes. Final low-pass diagnostic maps use the state FSC resolution when available, otherwise the supplied final fallback LP.

    Every completed run also writes solve3D_manifest.txt last, atomically and never fatally, and registers it in projinfo by bare name with its run identifier (simple_solve3D_manifest): the project identity, the particle source, the solution, the ladder as planned and emitted, the entry inputs, content digests of the state maps, halves and FSCs, and a cheap committed-header and global-section identity for sigma2. Sigma particle spectra are not scanned to write or validate the manifest. A failed manifest write warns and leaves the run as it is.

    11. solve3D_addon¶

    solve3D_addon projfile=<current> projfile_frozen=<solve3D or solve3D_addon run project> extends a completed solution with the particles the current project adds (the cohort); the frozen particles contribute their accumulators unsearched. Its policy is solve3D_addon_policy.md; the design history is in doc/implementation_notes/completed/abinitio3D_addon_mode_proposal.md. In short:

    • Only a solve3D or solve3D_addon output whose manifest validates against its project is accepted, so add-ons chain; the solution's settings are replayed from the manifest and refused on the command line, which carries only the 11 add-on inputs.
    • Both projects must share one particle index space: row i names the same image in both wherever both hold a row i, and they may differ in size. Rows the current project appends past the frozen project's last row (a stream's later particle sets) join the cohort; appended rows from a stack the frozen project holds are refused. Every frozen particle must lie within the current project's rows and be active there. The cohort needs at least 5 particles per inherited state (a warning below 5 % of the frozen population).
    • The execution-environment keys pass through, the stream's persistent-worker keys (worker_server, worker_priority) included.
    • The run searches the cohort in the last stage of the base run's planned ladder (read from its manifest), after one registration pass, with center=no and overlap 0.95 by default (it applies when that stage is stage 3); the stage limits follow the rule above (FSC=0.5 promotion from the union FSC, the NU handoff in the NU stages), and the stage logs them next to the base run's.
    • The run ends with a validation report against the base solution (solve3D_addon_report.txt in the run directory, and the log): per state the FSC verdict (improved or regressed beyond one FSC=0.143 shell, else unchanged), the union map's correlation with the base map up to the base resolution (docked below 0.9), the cohort-only map against the base map with addon_diag=yes, and both runs' stage limits. A regression is warned about; the result is published all the same.
    • The final reconstruction is incremental (calc_final_rec_addon): it reads the cohort's particles and the carried frozen sums, never the frozen particles, seeds no sigma from image power, commits the cohort's new sigmas in a residual pass and ships the union map with the frozen rows restored (solve3D_addon_policy.md section 8).
    • mkdir=yes by default; mkdir=no is for NICE. When the run has completed, the finished project (every particle posed, the union's sigma2 state) replaces the current project file; the frozen project is never written. The add-on's own manifest is eligible: the output is the frozen input of the next add-on.
