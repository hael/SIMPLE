    The center student's ceiling: is there anything left for a centring network to win?¶

    Status, 2026-11-18: stopped by Hans after Phase 0 and the first seed of M1; the center student rejected (rejected/center_student.md). Run center_ceiling on the dell. Base: a26f57437. Supersedes: none. Decides the fate of rejected/center_student.md (not launched). Depends on: the class student on raw picks with the alignment over its shortlist (validated: yes, completed/class_student_raw_picks.md); the pose student's centring policy (validated: yes, ruling R7 of planned/pose_student_physical_raw_picks.md, adopted in a26f57437); validate_class_student's read at the reference's shifts (validated: yes).

    In one paragraph¶

    rejected/center_student.md proposes a real-space network that centres raw picks before the class student. Two cheaper measurements bound what any such network could win, and this run makes them before anything is built. M1, the class student's ceiling: give the class student the full search's own shifts (perfect centres), and the same shifts blurred by the error a good network would make, then align over the disk as today. Compare the class averages with today's route on raw picks. M2, the pose student's link: under ruling R7 the pose student predicts at 2D shifts, which in the stream come from the class student's alignment, not from a full solve2D. Compare the pose student's unseen map at the class student's shifts with the map at solve2D's shifts. If perfect centres do not improve the class averages and the class student's shifts serve the pose student as well as solve2D's, no centring network has a consumer, and the center student is rejected.

    1. Why¶

    • The class student on raw picks with the alignment over its shortlist (SK) already gives class averages finer at FRC 0.5 than the full search's own (seed 1: streptavidin 12.50 against 13.05 Å, bgal 13.65 against 14.14 Å, trpv1 14.68 against 21.13 Å; completed/class_student_raw_picks_report.md). Where the aligned class is the reference's, the aligned shift is the reference's to rounding. Its shortlist holds the reference's class for 94 to 99%.
    • The route through center_ptcls lost to raw picks + SK by 0.75 to 4.80 Å at FRC 0.5.
    • The pose student needs centred particles: on streptavidin its cone held the reference for 70% of particles at the 2D shifts against 19% on raw picks, and the unseen map went from 8.93 to 4.90 Å at FSC 0.143 (pose_raw, R7). In the stream those 2D shifts come from the class student's alignment. That link has never been measured: the pose run's 2D shifts came from a full solve2D over the whole set.
    • By ruling R5 of the pose run (and the class student's experience) the maps and class averages decide; agreement reads are diagnostics.

    2. Contract¶

    • No change to the tree's source. Every arm is a variant patch on a git archive export under scratch/keep/variants/. The only tree edits are documents (section 8's file table).
    • No new command-line key in the tree; the variants may add developer keys to their own copies.
    • The class student's and the pose student's code are read, not edited. Costs are reported, never gated.

    3. Decisions¶

    1. Data. The three real sets of the earlier runs:
    set class student (M1): import project, nsample ncls mskdiam pose student (M2): selection project, settings
    streptavidin /data/10335-streptav/tst/1_import_particles/tst.simple, 5000 30 85 /data/10335-streptav/tst/3_selection/tst.simple, as pose_raw
    bgal /data2/bgal_addon/1_import_particles/bgal_addon.simple, 2500 50 180 /data2/bgal_addon/3_selection/bgal_addon.simple, as pose_raw
    trpv1 /data2/trpv1_c2/1_import_particles/trpv1_c2.simple, 2500 50 175 /data2/trpv1_c2/3_selection/trpv1_c2.simple, as pose_raw

    Checksums recorded in Phase 0; a changed or missing file is a stop. 2. M1's arms, all inside one validate_class_student run per set and seed (one teacher, one model, one reference, one unseen set), seeds 1 to 8: - A_raw: today's route (raw picks, the shortlist, SK over the disk under the pick prior); - A_σ for σ ∈ {0, 1, 2, 3, 4} Å: every unseen particle's stored shift set to the full search's shift plus an isotropic Gaussian error of σ per axis (keyed by the seed and the particle, the same draw in every arm), then the prediction and SK over the disk about that start, sentinel and pick prior as predict_classes sets them. A_σ is the class student behind a centring network of error σ; A_0 is the perfect centring network. For scale: two converged solve2D runs agree within 3 Å for 69 to 76% of particles (about 1.3 Å per axis each), and the best measured centring baseline puts 57% within 3 Å (about 2.3 Å per axis). As wired in Phase 0 (variant V1): the arms run after A_raw is complete (its teacher, model, reference, prediction at the reference's shifts and class averages), so A_raw is untouched; each arm starts again from the teacher's result project, sets the stored shifts, runs predict_classes unchanged in predict_sig<σ>/ and makes its class averages there. The error is one standard normal pair per particle from SIMPLE's keyed generator (the run's SIMPLE_SEED and the particle's row), scaled by σ in every arm. Each arm's reads go to one table, validate_class_student_arms.txt, with A_raw's row computed by the same code (equal to the report's). 3. M1's reads per arm: the class averages' FRC 0.5 crossing (Å) and mean FRC to 15 Å, as validate_class_student reports them; diagnostics: the shortlist's hold on the reference's class, the mode's and the committed class's agreement, the committed shift's error against the reference's (median, 90th percentile). As read from Phase 0: the FRC 0.5 crossing that decides is the report's line "Class averages vs the teacher's, FRC 0.5 (A)", the median over the compared classes of the crossing interpolated between shells (frc05i_A in the arms table). As in the report, an arm compares the classes holding at least 10 unseen particles both in its own assignment and in the reference's, so the compared set can differ by a class or two between arms (ncmp). Clarified by ruling R4 (the maintainer's session, 2026-11-18, before any verdict): the arms are compared over one class set. The compared set moving between arms shifts the medians by amounts near the 0.3 Å margin. On bgal at seed 1 it held 36 classes for A_raw and 35 for every A_σ, and the reference's own median moved from 13.51 to 13.32 Å with nothing else changed. So per validation, the paired reads use the classes holding at least 10 unseen particles in the reference, in A_raw and in every A_σ alike, and their count and the classes dropped are recorded. The read that decides V1 is the interpolated FRC 0.5 crossing, the median over that common set; the mean FRC to 15 Å over the same set is reported beside it. The crossing in whole shells moves in steps of a shell (1.2 Å on streptavidin) and is reported only. The per-arm columns as the report computes them stay beside. To make this possible, V1 writes every arm's per-class FRC reads to validate_class_student_arms_classes.txt. The validations made before the ruling kept no per-class numbers and were rerun. 4. M2's arms, on the pose run's frozen models: the physical teacher's 27 trained students (nine teacher-and-seed pairs per set, /data2/agent_runs/pose_raw/scratch/keep/val/P3/) predicting the same unseen particles with the alignment over the cone, as the pose run's arm C3SK (its variant scratch/keep/variants/C3 there): - C_2D: the unseen particles at their solve2D shifts (the pose run's C3SK input); - C_CS: the unseen particles at the class student's aligned shifts. Both arms run on one build: the C3 variant's sources (on fd9af0add, where the models were trained) linked with -static-libgfortran (the heap-corruption fix of 68638be28, link only), plus the patch that reads C_CS's shifts. C_2D is rerun on that build, not taken from the pose run's tables; its numbers are compared with the recorded C3SK's as a check. As wired in Phase 0 (variant V2): the pose run's C3 source tree is copied as it is: fd9af0add with that run's uncommitted pose-student changes, on which the models were trained, plus its C3 patch. V2's patch adds the developer key infile2, a file of rows "particle, x, y" in pixels. Given it, validate_pose_student replaces the unseen particles' input shifts with those rows, and every unseen particle must have one (arm C_CS). Without it the run is C3SK unchanged (arm C_2D). By ruling R3 the pose run's teachers and models are read in place, never written; their checksums are verified before and after the runs. 5. M2's class students. Per set, three class students (seeds 1 to 3), each as validate_class_student builds it at the current base: a solve2D teacher on nsample particles at their picked positions (the 2D shifts zeroed, the sentinel set), learn_class_student, then predict_classes with SK on the pose student's unseen particles at their picked positions. The teacher's draw excludes the pose student's unseen particles (Phase 0 checks that the unseen half is the same for every pose pair of a set; if it is not, the draw excludes their union). Pose pair (teacher t, seed s) uses class student t. The class student's settings are decision 1's M1 settings (ncls, mskdiam) on the selection project. Revised in Phase 0 under ruling R2 (how the class students are drawn and built): - The unseen half is the same for every pose pair of a set. The pose run splits its training and unseen particles greedily by class score, with no seed, so no union is needed. The halves hold bgal 1 256, strep 1 821 and trpv1 30 504 particles, all of them selected. - The base programs cannot keep given particles out of validate_class_student's training draw. A by-hand chain (selection on the teacher's result project) would leave the training particles' classes and the class records' states in the project, and those change the references predict_classes prepares. So the class students run on a third small variant, VCS: the base plus the developer key infile, a list of rows. Given it, those rows are the unseen particles and the training draw takes min(nsample, rest) of the other active particles. Everything else is the base's validate_class_student. - The input is the import project, which holds the same particle in every row as the selection project (checked: stack, index, defocus and astigmatism agree on every row). It is given the selection's states with the base program selection. The teacher's particles then enter exactly as in M1: at their picked positions, with the import project's untouched fields (shift 0, no class). - nsample is decision 1's, capped at what the draw has left: bgal 1 500 (the whole remaining pool, below 2 500), strep 5 000 (the whole pool), trpv1 2 500 of 5 000. The class student's committed shifts of the unseen rows (its prediction table's x and y) are C_CS's infile2. 6. M2's reads per arm: the unseen map's FSC 0.143 and 0.5 crossings (Å) against the teacher's map, as the pose run read them (beside fsc0143_reference_A); diagnostics: the cone's hold on the reference direction, the committed direction within 6°, the committed shift's error, and the class student's input shifts against the solve2D shifts (median and 90th percentile, Å). 7. Verdicts, written now. One-sided 95% bounds of the paired mean difference: M1 over eight seeds (t₇ = 1.895), M2 over nine pairs (t₈ = 1.860). The margins are the center student plan's: δ_FRC = 0.3 Å for class averages, and the same 0.3 Å for the unseen map (δ_map). Lower Å is better throughout. The first branch that holds applies. - V1, the class student's ceiling, on g_σ = FRC₀.₅(A_raw) − FRC₀.₅(A_σ) (positive: the centred start is better; FRC₀.₅ is the interpolated crossing's median over the validation's common class set, ruling R4, decision 3): - no headroom if UB(g_2) < δ_FRC on every set; - headroom if LB(g_2) > δ_FRC on at least one set (record g_σ for every σ: the size of the prize); - otherwise inconclusive. σ = 2 Å decides because no measured centring reaches it; A_0 is reported as the absolute ceiling. - V2, the pose student's link, on h = FSC₀.₁₄₃(C_CS) − FSC₀.₁₄₃(C_2D) (positive: the class student's shifts are worse): - no gap if UB(h) < δ_map on every set; - gap if LB(h) > δ_map on at least one set; - otherwise inconclusive. - The outcome: - V1 no headroom and V2 no gap: the center student is rejected. Phase 2 records it (section 8). - V1 headroom or V2 gap: stop with the tables; the maintainer decides whether the center student is rescoped to that consumer. - Any inconclusive verdict: stop with the tables.
