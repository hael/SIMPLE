    Multi-state ab initio: find what broke, restore what worked, until it separates¶

    Plan of 2026-11-06 for the autonomous run ms_abinitio on dell2. Written after two runs on Afan's three-state benchmark (ms_posterior, ms_posterior2; the second's report is doc/implementation_notes/completed/multistate_posterior_state_draw_report.md) and Hans's account of what worked: multi-state ab initio from a random partition of the particles into states (the 2025 paper, het_mode=independent) resolved many states on real data, and straight stochastic hill climbing with sampled in-plane angles worked surprisingly often; a single-state solution split afterwards never worked on real data.

    Unlike the last run, this run does not stop at a verdict. Its goal is a de novo multi-state solve3D that separates the benchmark's states, and it keeps working the candidate list below until that holds, the list is exhausted, or a stop condition of section 3 is met.

    1. What is known¶

    The benchmark (/data2/multistate_bench on dell2, read-only): 80,000 simulated particles, 128 px at 3.0 A, SNR 0.01, three ribosome assemblies of 24,000 (state 1, smallest), 48,000 (state 2, medium) and 8,000 (state 3, largest). True labels, poses and maps are given. cryoSPARC's ab initio recovers the states (the README).

    What the earlier runs measured (current code unless named):

    • With the true poses and the truth maps as references, every particle is assigned its true state at 10 A. The state signal is there.
    • From random balanced labels on the true poses, on the 20,000-particle subset S (6,000 / 12,000 / 2,000), two runs ended at accuracy 0.69 and 0.65: the smallest assembly separates, the medium is split over two states, the largest is merged into one of them. The joint state draw and the old argmin behave alike here. (Corrected in Phase 1: run 2 compared the two rules on the small labels route only, never on S. On S, label recovery is a stochastic fork for every build tested, see Phase 1's Progress.)
    • Three de novo runs on S ended at 0.59, 0.42 and 0.58; the current code's de novo run of the full set before the October posterior change ended at 0.45 (not paired).
    • In every de novo run the two hill-climbing stages reached 0.42-0.45 (chance is 0.34), and the first probabilistic iteration re-drew about half the labels and erased it (stage 3 at 0.38-0.40). The state posterior at the search's factor 0.3 spreads over 2.2-2.7 states at 20-23 A, and a quarter to half of each state's mass sits on entries the fill did not shift-refine.
    • On S the 2D classes reach 22.6 A, so the five multi-state stages ran at 24, 22.6, 22.6, 20.2 and then 6 A.
    • The small simulated tests pass: multistate_workflows suite=labels resolves every state in 13 of 20 seeds (gated at 6), suite=shc in 15 of 20 (gated at 6). They do not reproduce the benchmark's failure.

    How the code changed since the method that worked (the 2025 paper, Acta Cryst. D 81, ic5124; code tag v3.1-beta, 2025-05-27):

    What The paper's code Now When
    Early search stages 1-4 shc_smpl: hill climbing over directions with the in-plane angle sampled within an angular neighbourhood (10 degrees to start, adapted) stages 1-2 shc with the best in-plane angle; shc_smpl deleted default changed about 2026-04; deleted 2026-10-06 (dffa21364)
    Probabilistic draw sampled within the angular neighbourhood of the best candidates (prob_athres), with a reference-balanced frontier (every reference draws its closest free particle) one draw from the whole row's tempered posterior (prob_beta 0.3), no neighbourhood, no frontier 2026-10-24 (811934ca5)

    Cyril reported that multi-state stopped working on 2026-10-20; the build of 2026-10-15 (1bbbdcc24) still separated his two-state set in 2 of 4 runs.

    2. Rulings¶

    1. Multi-state ab initio from a random partition of the particles into states. No single-state solution split afterwards, no flex initialisation, no docked mode (Hans, 2026-11-06).
    2. Hard state labels in the reconstructions (2026-11-03). If the evidence says only soft state membership can separate the benchmark, the run stops and writes that up.
    3. No new parameter of any kind (every field of simple_parameters becomes an accepted key of every program). A search mode that existed before may come back as a value of the existing refine key; the solve3D controller chooses the modes per stage and state count, as it does now. Experimental variants are patches applied to git archive exports in scratch, never keys.
    4. nstates=1 stays bit for bit identical at one thread (single-state solve3D was just optimised; protect it). A change that cannot be confined to nstates>1 is a stop.
    5. No floor, tolerance or timeout of an existing test is relaxed. New floors come only from a profile of the finished code by the floor rule.
    6. The benchmark drives the development this time. Decisions are taken on it, on the fixtures of section 4, in the order section 5 sets.
    7. State 0 is exclusion; a true state in state 0 is a failure. A de novo verdict rests on several runs, never one.
    8. Stream code and the GUI are not edited; the 2D tables are not changed.
    9. No de novo runs with the old builds (Hans, 2026-11-07, on the Phase 0 diagnostics so far). Phase 0 ends with A25's label recovery on S and HEAD's label recovery on S at the full set's update fraction (0.375); the de novo runs of A25 and A1015 in Phase 0's step 3 are dropped, and the diagnostics are read by Phase 0's table without them.
    10. No freq_march_aggressive (Hans, 2026-11-08; the key is to be removed): no test or candidate uses it. The ladder hypothesis (C3) is tested with the explicit-limits path that exists, lpstart=<A> lpstop=6 force_lp_range=yes on the solve3D command line (a linear ramp from lpstart to lpstop over the stages, taken as given), with an lpstart that does not sit at the 2D classes' 22-24 A, combined with C1 and without it where the evidence needs it. If the forced ramp is what separates the states, the candidate kept is a controller default for nstates>1 that plans a linear ramp instead of the class-FRC ladder (no new key), nstates=1 unchanged.
    11. The balanced subset B judges Phase 2 (2026-11-08, the maintainer's delegate). With the true poses S separates in label recovery only by a race over the largest assembly's 2,000 particles (HEAD 2 of 6, the paper's code 2 of 2), and every de novo candidate on S ended at 0.41-0.47 after stage 4, whatever it changed. So candidates are judged by de novo runs on B (8,000 of each assembly; label recovery on true poses separates it reliably). B's 2D solution is made first (solve2D ncls=30 mskdiam=300 nthr=16 on a copy of PZB, as P2S was made). Before any candidate, one de novo run of HEAD unchanged on B: if it separates, HEAD de novo on F follows before anything is built. The stopping rule (a de novo run below 0.60 after stage 4 is stopped) and the candidate order stay. S stays in the report as a stress case with its counts.
    12. The target is SNR 0.05 (Hans, 2026-11-08, after Cyril reported success on real data with the code this run started from): "SNR=0.01 is kind of intense. I'd be happy with code that can cope with SNR=0.05." Afan's SNR 0.01 benchmark stops driving the development; its findings (the rare-state race on S, no regression, the 2D-pinned ladder, HEAD de novo on B at 0.699, C1 and C3 below HEAD) are kept as a stress case. A benchmark F05 is simulated at SNR 0.05 by Afan's recipe (80,000 particles, the three truth maps, populations 0.3 / 0.6 / 0.1), its truth checked as in Phase 0, with its project and 2D solution under scratch/keep/. HEAD unchanged de novo on F05 twice, then true-pose label recovery once. If HEAD separates both runs, no code change is needed (Phase 4 next; Phase 3's gates apply only to a kept change); one of two -> a third run decides (2 of 3); if HEAD fails, the candidates (C4, C2, then C1 and C3 if the evidence favours them) are judged on F05 with HEAD's runs as the bar. C2 is not run on the SNR 0.01 data.
    13. C5 first on F05 (2026-11-09, the maintainer's delegate).
