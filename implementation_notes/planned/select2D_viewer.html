    select2D in its own executable, simple_viewer, saving into a new selection folder¶

    Status, 2026-11-25: approved by the owner; Phases 1-3 written, not yet built (Phase 0 and every exit run on the owner's Mac). Base: 2750c34ac (clean tree). Supersedes: select2D.md decisions 2 and 4, the mkdir=yes part of decision 3, and the executable/router/category part of decision 1 (its banner says so in the same commit). Owner: Dibyajyoti Maity. Depends on: - select2D as committed in 2750c34ac (built and run by the owner on the Mac, 2026-11-25; validated: yes); - prg=selection oritype=cls2D (exec_selection, simple_commanders_project_core.f90) as the reference semantics of a class selection and of its output folder (validated: yes, in production).

    1. Why¶

    select2D today is simple_exec prg=select2D: simple_exec links GTK 3 for one program, and with mkdir=yes params%new makes <n>_select2D/ and copies the project there the moment the program starts, so a session that is only looked at, or closed without saving, leaves a folder and a project copy behind (a 435 MB 1_select2D/ was left in the checkout on 2026-11-25). Save then writes four segments into that copy with write_segment_inside and a selection.txt beside it. The owner's ruling (2026-11-25): select2D becomes a separate executable, simple_viewer, which for now launches the select2D GTK application and nothing else; nothing is written until Save selection; Save writes a new project into a selection folder named and placed as prg=selection names and places its run folder, through the routines prg=selection uses; no selection.txt.

    2. Contract¶

    • simple_viewer prg=select2D projfile=<p>.simple opens the select2D window (prg= first and required since decision 15); there is no append= (decision 14: simple_viewer stops on one).
    • simple_exec no longer offers or routes select2D and no longer links GTK (otool -L / ldd of simple_exec lists no gtk). simple_exec prg=select2D stops in cmdline%parse with "select2D is not executed by simple_exec but by simple_viewer" (no alias; release 4 keeps no compatibility).
    • Opening a project and closing the window without a Save creates no directory and writes no file. The input project is never written (byte-identical before and after a session, saved or not).
    • The first Save produces <n>_selection/<input basename>.simple in the input's workspace root (decision 13); later Saves of the session rewrite that file. Its segments equal those prg=selection oritype=cls2D infile=<the same 0/1 states> append=no writes from the same input, except the declared exclusions of decision 12 (the folder in the projinfo paths, and the jobproc row that records the job: prg=select2D here, prg=selection from simple_exec's front door there).
    • prg=selection is unchanged (no edit to exec_selection).
    • Off-state: no program other than select2D changes behaviour; only simple_viewer and simple_test_exec link GTK.

    3. Decisions and rulings¶

    1. (2026-11-25, owner) select2D runs in a new executable simple_viewer only. Its UI entry and router case leave simple_exec; production/CMakeLists.txt links SIMPLE_GTK_LIBRARIES to simple_viewer (and simple_test_exec, as now) instead of simple_exec. Replaces select2D.md decision 2.
    2. (2026-11-25, owner: "simple_viewer is the executable that launches the select2D gtk application for now") Command line: simple_viewer projfile=<p>.simple, no prg= (the [append=yes] first written here is removed by decision 14). cmdline%parse gets one case for simple_viewer: its program is the one program the registry holds for that executable (new get_executable_prg in simple_ui.f90, which stops unless there is exactly one), so the name select2D lives only in the UI descriptor; every argument is a key=value (no program slot in the count of required arguments); prg is set on the cmdline after parsing so params%new sees select2D; a prg= on the line is accepted only if it names that program (so a launcher that always writes prg= still works), any other stops; no argument at all prints the usage and stops, as simple_exec prg=<x> alone does; describe=yes and usage=yes work as elsewhere. A second view later is the owner's decision then (this rule then stops with "more than one program").
    3. (proposed) Front door production/simple_viewer.f90 (about 35 lines, the shape of single_exec.f90): make_ui, cline%parse, the router, git version and timer. It does not call update_job_descriptions_in_project (layering policy section 8 lists front-door project writes as a deviation not to extend; decision 8 records the job instead), script_exec (a window is not queued) or the memory monitor. One router, src/main/exec/simple_viewer_views.f90 (exec_viewer_commander). No API umbrella module (compile-time policy): the front door imports with only:.
    4. (proposed) UI: the select2D descriptor moves from simple_ui_cavgproc.f90 to a new category module src/main/ui/simple/simple_ui_viewer.f90, category ('viewer', 'Viewer', 10), constructed from simple_ui_simple_group.f90, executable 'simple_viewer'. Inputs: projfile, required as now (append removed by decision 14); visibility Standard (select2D.md decision 19 stands); the help says that nothing is written before Save selection and where the selection goes.
    5. (2026-11-25, owner) Nothing on disk at start: the commander sets mkdir=no unconditionally (over any mkdir= given), so params%new neither makes a directory nor copies the project. Replaces the mkdir=yes of select2D.md decision 3. The display check before params%new (select2D.md decision 15) stays.
    6. (proposed) Start-up reads only the cls2D and out segments of the input (read_segment), all the window uses (select2D.md decision 8: rows, pop, res, state, the cavg stack of out); the particle segments are read only at Save. Today the whole project is read at start.
    7. (2026-11-25, owner) The first Save makes <n>_selection/ in the directory the viewer was started from (params%cwd), with n = find_next_int_dir_prefix(<that directory>): the name, number and place setup_execution_context gives prg=selection's run folder under mkdir=yes (int2str(idir)//'_'//prg).
