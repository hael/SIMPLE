    Report: the class student on raw picks¶

    Run class_raw, 2026-11-16, on the Dell, unattended. Plan: class_student_raw_picks.md (beside this report; its Progress section holds the detail). Base: 1637eeb1c. Outcome: adopted (ruling R4), uncommitted for review.

    The class student no longer centres new particles. It predicts on the raw picks, then aligns each particle against the teacher's class averages of its candidate list (every in-plane rotation, shifts over a 30 Å disk) and commits the best alignment. Against the old route through center_ptcls it agrees more often with the full search's class and gives sharper class averages on all three data sets, at a cost per particle 2.3 to 17 times lower. It costs less than the full search on bgal and trpv1 and more on streptavidin. The plan's rule required "less" on every set, so the run stopped once at that rule. The maintainer waived it for streptavidin, a 30-class set where the full search is already cheap. The amplitude channel was tested and rejected, and the idea has been removed from the docs.

    Terms. The class student is a small network trained on a solve2D run (the teacher). For each new particle it gives a ranked list of likely classes: its candidate list, the classes holding 99% of its posterior, at most 16. A confident particle's list is its shortlist. The reference throughout is the full search: each unseen particle's best class under the physical posterior over all of the teacher's class averages, every rotation and the 30 Å disk. Particle counts: streptavidin 11,402 (5,000 teacher particles, 30 classes), bgal 5,513 (2,500, 50 classes), trpv1 35,645 (2,500, 50 classes). Every comparison is eight seeds, paired by seed, with the paired standard error (SE) in brackets. "Beyond 2 SE" is the plan's significance rule.

    1. What was learned¶

    Dropping centring alone costs accuracy but keeps the candidate list (Phase 0). C0 is the base with center_ptcls; R0 is the same validation with the unseen particles at their picked positions and the old local shift registration:

    R0 − C0 streptavidin bgal trpv1
    candidate list holds the reference's class (points) −1.9 (0.5) −1.8 (0.7) −0.7 (0.3)
    most likely class is the reference's (points) −5.6 (0.8) −15.7 (0.9) −19.3 (1.0)
    route's cost (ms per particle) 8.92 → 0.16 3.25 → 0.65 1.98 → 0.40

    On raw picks the list still holds the reference's class for 89.5 to 96.4% of particles. The plan's early stop (decision 8, below half) therefore did not apply, and aligning over the list was worth testing. The old local registration does not centre raw picks: its shift misses the reference's by about the picking error itself (7 to 9 Å median).

    Align against the candidate list (SK), not the most likely class alone (S1) (Phase 2, decision 7 (a); one validation measured both on the same prediction):

    SK − S1 streptavidin bgal trpv1
    aligned class is the reference's (points) +7.4 (0.4) +19.3 (1.0) +37.9 (0.5)
    class averages, FRC 0.5 crossing (Å) −0.43 (0.13) −2.31 (0.74) −4.26 (1.14)
    alignment's cost (ms per particle) +0.36 +0.49 +0.41

    Where the aligned class is the reference's, the aligned pose equals the reference's to rounding. The alignment reuses the same shift-map search from the same start.

    The amplitude channel (Phase 3, decision 7 (b)). B adds an amplitude path to the network beside the complex one; B' is the same with each particle's amplitudes taken from another particle (the capacity control); C is the amplitude path alone (the wiring check). B was worse than the tree on reads of every set: streptavidin's aligned class −4.7 (0.9) points, bgal's class averages 0.65 Å coarser at FRC 0.5, trpv1's share shortlisted −10.0 (3.5). Its one large gain, bgal's aligned class at +8.0 (0.8) points, B' showed too, at +6.0 (0.7), so it comes from extra capacity, not from the amplitudes. C recognised 2D classes (0.484 of bgal's held-out classes), as expected for an amplitude path: shift-invariant and unable to resolve a half turn. The amplitude channel was tested on the class student 2026-11-16 and rejected; not to be revisited.

    Dropping centring: better quality on every set, cost above the full search on streptavidin only (Phase 4, decision 7 (c)). The tree (SK, no amplitude path) against C0:

    SK on raw picks − C0 streptavidin bgal trpv1
    committed class is the reference's (points) +2.6 (0.8) +4.4 (0.9) +17.4 (0.9)
    class averages, FRC 0.5 crossing (Å) −0.75 (0.13) −2.93 (0.73) −4.80 (1.27)
    class averages, mean FRC to 15 Å +0.043 (0.012) +0.052 (0.010) +0.052 (0.021)
    route's cost (ms per particle), C0's route → the tree's 8.92 → 0.54 3.25 → 1.16 1.98 → 0.85
    route against the full search (ms per particle) 0.537 vs 0.442 (above, 8 of 8 runs) 1.162 vs 1.271 (below) 0.853 vs 0.923 (below)

    Phase 2's runs give the same picture. Streptavidin fails on cost because the list cap is fixed: with 30 classes the cap of 16 means SK aligns each particle against about half of all classes (15.98 on average). Ruling R4 waived the cost condition for this set: the full search there costs 0.44 ms, and small data sets decide nothing.

    The final tree at seed 1 (the adoption's validate_class_student run, beside C0's seed 1). One seed only: the 24-thread solve2D teacher is not the same twice, so these numbers do not repeat Phase 3's seed 1.

    seed 1 streptavidin: route C0 bgal: route C0 trpv1: route C0
    committed class is the reference's (%) 28.8 28.8 53.2 52.4 72.9 52.1
    class averages, FRC 0.5 (Å); the reference's 12.50; 13.05 13.16 13.65; 14.14 18.61 14.68; 21.13 24.23

    The student's class averages cross FRC 0.5 at a finer resolution than the reference's own on all three sets. The shortlists hold the reference's class for 96.6% on bgal and 99.3% on trpv1. On streptavidin the student shortlists 9 of 6,402 particles, 8 of which hold the class (the report marks 88.9% as not met; the eight-seed mean is 94.0%).

    2. What changed, phase by phase¶

    The diffs are in /home/elmlundho/agent_runs/class_raw/review/phase_N.diff.

    • Phase 1, the alignment after prediction: 12 files (+967, −315).

    3. Decisions taken under delegation¶

    Each is recorded in the Progress entry of its phase.

    • Phase 1, the search: the alignment reuses shiftmap_srch and the commit rule of the classic 2D search. A class keeps its refined pose only when that pose scores above the class's score at the stored shift, and the class with the best score wins.
    • Phase 1, the centring state: particles are marked not yet centred before the alignment. Afterwards their centring state records the move, as a 2D search or center_ptcls leaves it.
    • Phase 1, the settings: when predict_classes is given class averages, it sets the prior width, the window and the physical temperature of the reference pass.
    • Phase 1, the times file: the wall times of prediction and alignment go to a separate file (class_student_times.txt), because the prediction table must stay byte-identical between a run in parts and a shared-memory run.
    • Phase 1, the angle: the recorded angle is wrapped into [0°, 360°), the student's own convention. The workflow test's record gate caught a value of 360.0.
    • Phase 2, the class averages' comparison: only classes populated by both the student's and the reference's assignments are compared.
    • Phase 3, the variants' design and controls:
    • B' takes its partner from a fixed keyed permutation in training and from the batch's next particle in prediction;
    • in the gradient check, an entry whose every finite-difference step switches a ReLU is reported, not judged, with a guessed bound of at most one in twenty;
    • the tree was re-run beside B and B' so all three arms share the same tools and machine conditions.
    • Phase 4, what R4's removal covers:
    • also removed, as amplitude proposals: the "front end of Fourier moduli" among the shift-robust alternatives in polar_student_future_directions.md section 2, and its pitfall sentence;
    • kept, as a recorded command output: the git status listing in student_inplane_posterior_report.md, the one place that still names the deleted file;
    • in student_inplane_posterior.md, the launch's list of dirty files now reads "a planned note since deleted", so its count of five and its line counts stay true.
    • Phase 4, the gates' reuse: the tree's source has not changed since Phase 2; the rebuild recompiled only the version string. The plants of Phase 1 were not re-planted: the alignment module is byte-identical to the copy they ran on, and the tester has only been renamed since.

    4. Deviations from the plan¶

    • Decision 7 (c) was not met as written. The run stopped and wrote a stop report. Ruling R4 waived the cost condition for streptavidin and adopted the route. The plan records this in decision 7 (c) and in Progress.
    • C's wiring check was revised under ruling R2 and confirmed by R4. Decision 3 guessed a bound: at most 0.10 of the held-out classes recovered. C reached 0.484. The check became the path's own contract, with thresholds set after C's run:
    • shift-invariant reads, measured within 0.2 points;
    • the half-turn ambiguity of the angle, 56% at the opposite angle against B's 2.5%.
    • Files outside the original table, each given a row before its edit:
    • the alignment class and its tester (R3);
    • the suite table and the test UI's help (R3);
    • the algorithm page and the test policy, which also gained Phase 2 (R3);
    • the five amplitude-removal documents, one of them deleted (R4).
    • An expected effect that did not occur: the amplitude channel did not help.
    • A base fault seen once: a segmentation fault in solve2D (sp_project's write_segment_inside, called from the refine2D strategy) in 1 of about 150 validations (run C0, bgal, seed 1). Re-runs and a bounds-checked Debug run passed. It lies outside this run's files and was not pursued.
    • A tooling fix: the interpolated FRC crossing, copied from the last run, returned the box size when the first shell was already below 0.5. It was fixed in Phase 0 and the affected rows were recomputed.
