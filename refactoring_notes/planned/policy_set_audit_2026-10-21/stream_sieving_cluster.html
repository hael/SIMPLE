    Audit C: stream and sieving_and_rejection policies¶

    Scope: doc/policies/stream/ (README, p00-p07 overviews, ipc, pool2D, reference_generation, restart, stream_3D_ingestion) and doc/policies/sieving_and_rejection/ (index, class_compatibility, model_cavgs_rejection, ptcl_sieve). Checked against src/main/stream/{,stages,master,shared,pool2D}, src/main/commanders/stream, src/main/sieve, src/main/cavg_quality, src/main/class, src/main/solve, the skills simple-main-stream, simple-cluster-cavgs-quality, simple-main-class, and the working tree as of 2026-10-21. Read-only; nothing built or run.

    Baseline result: names, files, routines, constants, test names and relative links in these 16 documents are almost all correct (every src/... and doc/... path resolves; every routine named in stream_3D_ingestion_policy exists; the README resource table, the IPC key table and the sieve sentinel list match the code). No document uses cluster2D or abinitio* as a living name. The problems are (a) the pool2D policy does not state how the pool calls refine2D and who owns the pool project during an iteration, (b) there is no statement anywhere of who owns which stream project file, (c) model_cavgs_rejection.md is stale on who calls it, (d) a lot of dated history is mixed into the policies.

    Two files in the working tree are new and untracked (not audited): doc/policies/README.md and doc/policies/layering_and_project_ownership_policy.md. Its section 5.1 ("A stream stage and the 2D pool each own the files they write. Two processes never write one file.") is the only ownership rule in the doc set; see the pool findings below for where the code does not follow it.
