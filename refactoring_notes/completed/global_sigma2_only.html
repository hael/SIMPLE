    Global sigma2 only: removing sigma_est=group¶

    Status: completed 2026-10-13 by an unattended run on the Oracle Linux test machine (section 12), uncommitted for review; the record of every phase is in section 13 and the review report is global_sigma2_only_report.md beside this file. Written as a refactoring plan on 2026-10-12. Rulings of the same day:

    • sigma2_convert is retired.
    • The renames of section 5 are accepted.
    • The incremental store reduction is decided by measurement (section 6).
    • The stream is part of this refactoring.

    The outline was revised the same day after a review; every claim below was checked against the code. Rulings on the revision, also of the same day:

    • The solve3D manifest key sigma_est leaves within manifest version 2, with no second version bump (section 4).
    • Existing global stores with the STAR-seed provenance are refused and rebuilt from particle power spectra, like stores written under group (section 4).
    • The science validation's full re-read of the store moves to the tests (section 6).
    • The streaming commit and the block-copying merges are part of this refactoring. The sparse ranges wait for a measurement on the ribosome project, which the test machine does not hold (section 6).

    1. Decision¶

    • sigma_est=group is no longer supported. Under it, each particle stack had its own noise spectrum per half.
    • Every workflow estimates one global noise spectrum per half: the average of the per-particle residual spectra. A half is the even or the odd half-set.
    • The sigma_est key goes, with every place that sets, passes or checks it.
    • The per-particle residual spectra (records) stay in the canonical sigma2 store (sigma2_state.bin). A fractional update replaces only some records, and the global average must reflect every particle's latest residual (doc/refactoring_notes/completed/canonical_sigma2_state_refactoring.md, section 2).
    • Release 4 keeps no backwards compatibility except for .simple project files.

    2. What group estimation costs today¶

    The choice between two policies is threaded through the code, and several expensive structures exist only because the spectrum could differ by stack.

    • A noise table per particle. At load, read_groups (simple_euclid_sigma2.f90) copies each particle's group spectrum into sigma2_noise(shells, fromp:top).
    • Under the global policy every column is one of two spectra.
    • At box 336 (168 shells) that is 67 MB per 100,000 particles in every process that loads it, and 504 MB at 750,000.
    • Shared-memory runs hold the whole project. FLEX and cls_expansion widen the range to the whole project even in distributed runs.
    • Reconstruction consumers (load_sigma2_groups) then copy the table again into sigma2_part (allocate_ptcls), and never use the copy.
    • Matchers hold the partition's records (read_part) next to the table. They update those records and write them back, so the records stay.
    • Per-particle indexing in the hot loops.
    • The polar correlation kernels (simple_polarft_corr.f90, 19 references) and the particle self-terms (simple_polarft_memo.f90, 4) compute real(k)/sigma2_noise(k,iptcl) per shell, per evaluation.
    • The access is contiguous: shells vary fastest for a fixed particle. The cost is a division per shell where a precomputed weight would do, and the size of the table.
    • wsqsum_ptcl_now (simple_polarft_memo.f90) recomputes a particle's weighted self-term over all shells on every call, because the memoised value may be stale relative to the table.
    • The GPU path builds and uploads a weight table wks(shells, nptcls) per batch.
    • Per-particle spectra in reconstruction and the other consumers.
    • gen_fplane4rec (simple_image_ctf.f90) receives the particle's column. For every particle it allocates and resamples it to the plane grid, rebuilds its shell lookup table, and divides by the spectrum or its square root per pixel.
    • The PCG path (simple_rec3D_pcg_strategy.f90) resamples every particle's column into sig2(0:R, nptcls). In the state-weighted path it then divides each column by the particle's weight.
    • Class-average restoration (simple_classaverager_restore.f90) passes each particle's column to gen_fplane4rec.
    • The Cartesian slots copy the column per batch (prep_cart_batch_of_build, simple_matcher_ptcl_batch.f90), and each slot of simple_cartft_calc.f90 allocates and validates its own copy.
    • cls_expansion fills a weight table w(ncoeff, nptcls) per class.
    • Class-average restoration reads records it never uses. cavger_read_euclid_sigma2 calls read_part, which reads the partition's per-particle records. Restoration only needs the spectra.
    • The store carries a grouping policy.
    • The header records the policy and the group count. The grouped section holds 2 × the number of groups spectra.
    • Every reduction, validation and commit takes an array of group identifiers built from stkind over all particles.
    • The policy check exists in three copies. Each validates the store, takes the layout digest and, under group, recounts stacks from stkind:
    • canonical_sigma2_consumable (simple_sigma2_files.f90);
    • the reconstruction start (simple_rec3D_strategy.f90);
    • the solve2D checkpoint resume (simple_commanders_solve2D.f90).

    The chunk merge (concatenate_canonical_states in merge_chunk_projfiles) and the merge_projects merge (merge_selected_canonical_field), both in simple_projfile_utils.f90, build the group arrays the same way. The chunk merge also serves project and class-average commanders and the sieve, not only the stream. - Group-only failure modes and workarounds. - A selection that empties one half of a stack makes the reduction refuse ("empty even/odd half"). Under the global policy only a selection that empties one half of the whole project does. - FLEX carries a fallback that detects this and switches to global (ensure_canonical_sigma_state). - cls_expansion probes both policies and flips params%sigma_est to whichever store it finds (prepare_flex_sigma2). - Command-line plumbing. - About 35 lines set sigma_est=global on a child command line, delete it, require it or warn about it. - Seven programs show it in their UI. - The solve3D manifest lists it as a recorded and replayed key.

    3. Target design¶

    • In memory (euclid_sigma2):
    • two global spectra, sigma2(shells, 2), one per half;
    • the derived arrays each consumer needs, per half and computed once: k/sigma2 for the polar kernels, 1/sqrt(sigma2) for the Cartesian slots, 1/sigma2 for cls_expansion. Reconstruction keeps its own copies on the plane grid (section 6). Each is a few hundred floats, so they stay separate instead of being derived from one another in the kernels;
    • the per-particle records of the pass's partition, only for a pass that writes residuals (the matchers).
    • Consumers address the spectrum or a derived array by the particle's half.
    • The polar calculator already knows each particle's half (iseven). The other consumers read it from the orientation (eo).
    • The reduction already requires every active particle's half to be 0 or 1, and the lookup refuses any other value. Today read_groups would index out of bounds for an active particle without a half, while class-average restoration files such a particle under even.
    • On disk.
    • The store keeps its version-two layout. The grouping word must be global and the group count 1, and the grouped section holds the two global spectra.
    • Existing global stores, the default everywhere, stay valid, except those whose provenance is the STAR seed (section 4).
    • A store written under group or with the STAR-seed provenance fails validation and is rebuilt from particle power spectra by the one rebuild entry below. Today that rebuild does not run everywhere.
    • One rebuild entry and one identity check.
    • canonical_sigma2_consumable(project, os, box, smpd, message) stays the identity check.
    • The rebuild moves into one routine in simple_sigma2_bootstrap.f90, the module that already owns the bootstrap. ensure_sigma2_for_iteration is the starting point; today it reads only the ptcl3D field.
    • Today each workflow rolls its own rebuild: refine3D's initialisation, the reconstruction start, the final reconstruction, the solve2D checkpoint resume, and ensure_sigma2_for_iteration for solve3D and FLEX. Three paths read or update the store with no rebuild in front:
      • refine2D checks nothing. Its first prepare_canonical_sigma_update validates the store and stops on failure.
      • make_cavgs opens the store through cavger_read_euclid_sigma2 without a check.
      • load_sigma2_groups checks and stops on failure, without rebuilding. It stays a hard check behind an entry that has rebuilt.
    • Every workflow entry that consumes or updates the store calls the central routine. Readers inside a pass (the matcher load, class-average restoration in a matcher) stay unchecked, because their master has run it.
    • This lands before the store refuses the stack policy (section 7).
    • The final reconstruction is the exception (decided in Phase 1). Its rebuild is bootstrap_rec3D, which seeds from particle power spectra and then runs a residual pass at the final sampling. A seed alone would skip that pass, so it keeps its own decision between reconstruct3D and bootstrap_rec3D on the one identity check.
    • The power-spectrum bootstrap.
    • The bootstrap (calc_pspec) already samples globally: at most 25,000 particles, split between the halves and drawn at random within each.
    • Its workers return per-half sums instead of a per-particle file. The normalisation stays exactly as it is (section 6).

    • The UI parameter sigma_est in simple_ui_params_common.f90, and its use by these programs:
    • refine3D and refine3D_auto (simple_ui_refine3D.f90);
    • refine3D_nano (single_ui_nano3D.f90);
    • flex_pca and refine3D_states (simple_ui_heterogeneity.f90);
    • sigma2_convert (simple_ui_other.f90).
    • solve2D's own sigma_est input (new_solve2D_descriptor in simple_ui_refine2D.f90). solve2D_chunks has no input, but its commander forces the value.
    • Every set, delete, require or warn of sigma_est:
    • simple_commanders_refine3D.f90, eight sites, including the bootstrap_rec3D warning;
    • simple_commanders_solve2D.f90, three sites;

    6. Optimisations¶

    Each item states what changes and how to measure it. A gain is claimed only from SIMPLE's benchmark files on the same run, before and after.

    • Memory.
    • Matchers keep their partition's records, because they update and write them. They lose the per-particle noise table: 168 floats per particle at box 336.
    • Reconstruction consumers lose both the table and the record copy (allocate_ptcls). Class-average restoration loses both the table and the records it reads. FLEX and cls_expansion lose both over the whole project.
    • Measure with the peak RSS that the refine2D and refine3D matcher benchmark files already record.
    • Weights computed once.
    • The kernels read k/sigma2 for the particle's half from a small array instead of dividing per shell per evaluation.
    • With the spectra fixed for the pass and each particle's half known at memoisation, memoize_sqsum_ptcl forms the weighted self-term once. wsqsum_ptcl_now becomes a lookup instead of a loop over the shells. This holds only if memoisation runs after the spectra are assigned; the order is checked when the change is made.
    • Measure with the "alignment search" timing of REFINE2D_BENCH_ITERnnn.txt and the refine3D matcher files.
    • Folding the weight into memoised transforms, to benchmark.
    • Folding it into the reference transforms (ft_ref, ft_ref2) misses the common case. When the reference is shifted, the kernel transforms the shifted reference afresh and never reads ft_ref.
    • Folding it into the particle transforms (ft_ptcl_ctf, ft_ctf2) covers shifted and unshifted references alike. They are memoised per particle, whose half is known, and the weight multiply leaves the inner loop.
    • The same particle arrays feed the correlation kernels (gen_corrs, the normalised-correlation gradient). Folded arrays therefore serve only passes that score with the Euclidean objective alone. Anything else would need a second copy of the particle memo, which is large.
    • The other Euclidean kernels that read the weight directly (the gradients, gen_many_euclids, the GPU kernel) are checked one by one.
    • The GPU path. Two weight vectors replace the wks(shells, nptcls) table built and uploaded per batch.
    • Reconstruction planes, cached for the grid's lifetime.
    • The two spectra are resampled to the plane grid once, together with the shell lookup table and the inverse and inverse-square-root spectra.
    • The cache is keyed by the store generation, the plane grid (padded box and pixel size) and the reconstruction mode. It is rebuilt only when one of them changes.
    • gen_fplane4rec then does no allocation, resample or division per particle. It multiplies by the cached arrays.
    • Class-average restoration uses the same cache, and the PCG path takes its per-half inverse spectrum from it (section 4).
    • Class-average restoration buckets particles by class.
    • cavger_update_sums loops over every class and, inside, over every particle of the batch, skipping the other classes' particles. Bucketing the batch by class once makes it one pass.
    • This is not a sigma2 change, but it sits in code this refactoring edits. Measure with the "class averaging" timing of the refine2D files.
    • No unused reads.
    • Class-average restoration no longer reads the partition's records.
    • Reconstruction consumers no longer allocate a record copy.
    • Fewer copies in the residual path.
    • calc_sigma2 allocates a contribution vector per particle, and store_contribution copies it into the record column. The residual routines write into the column directly.
    • read_part reads the records into a temporary and copies them, and write_sigma2 copies them into another temporary. Reading straight into the record array and writing straight from it removes both copies.
    • The power-spectrum bootstrap.
    • Today each partition writes a file with every one of its rows: zeros except the sampled particles, which are scaled.
    • The master reads each file twice. The first read sums by half. The second only learns the partition's row range, before writing the seed into the candidate.
    • At 750,000 particles that is 504 MB written and about 1 GB read, for 25,000 sampled spectra. The master then writes the seeded candidate and reads it twice more, for the reduction and the validation.
    • Instead, the workers write per-half sums of the rows they would have written, and the master takes the row ranges from the project.
    • The normalisation stays exactly as it is:
      • a sampled spectrum is scaled by nactive/(2 nsample) of its half, then sanitised: non-finite values become 1.0, and a spectrum with no value above DTINY becomes 1.0 throughout;
      • the master divides each half's sum by the half's number of active particles, sampled or not, which gives the sampled mean over two for every spectrum that was not floored;
      • it subtracts the average image's power over two, then repairs non-positive values (remove_negative_sigmas);
      • the average image is the sum of the sampled images whose spectra were valid, divided by the number of active particles in both halves (at the merge, by the number of images summed instead: section 15).
    • The selection stays the master's shared selection file, drawn per half. Drawing the sample inside the workers would change which particles are sampled, and with them the seed.
    • The master writes the seeded records in blocks. Every active row of a half holds the same spectrum, so the global spectra are known exactly and the reduction and validation re-reads go; the seed's validity is checked once instead of per row. When the committed prefix of an appended project is retained, its records are summed while they are copied.
    • Summation order changes, so the result is compared within tolerance, not bit for bit.
    • sigma2_binfile then leaves this path. Nothing else uses it, so the type and its re-export from simple_pftc_srch_api.f90 go too.
    • Store I/O per commit.
    • Today one matcher iteration reads the store five times and writes it three times:
      • each worker reads its partition's records (read_part) and writes them all back as a range file, updated or not;
      • the master copies the committed store into the candidate (sigma2_state_create_candidate), merges the range files into it (sigma2_state_merge_local_ranges), reduces it, and validates it (sigma2_state_validate_science), the last two each a full read;
      • each range merge opens the candidate, writes its rows and syncs the whole file (sigma2_state_write_particles). The candidate creation, the reduction and the publication sync again.
    • The copy is wasted. The merge requires the ranges to cover every row exactly, so every copied byte is overwritten.
    • A streaming commit, version two kept (ruled: part of this refactoring).
      • The master creates a fresh candidate at full size and fills it in row blocks. Each row comes from a range file if one covers it, otherwise from the committed store.
      • Every active, valid row is added to two real64 sums and counts as it passes. The master then writes the global spectra and syncs once, through one file handle.
      • With today's ranges, which cover every row, nothing is read from the committed store. The iteration then reads the store twice and writes it twice (the workers' record read and range write, the master's merge), with no format change.
      • The science validation's full re-read moves to the tests (ruled). The commit still checks coverage, counts and finite global spectra.
      • Range files stay until publication, so a failed commit can be rerun. Deleting each as it is consumed would save disk space and lose that.
    • Sparse ranges for fractional updates (ruled: after a measurement on the ribosome project, not in this refactoring).
      • Workers write only the rows they updated, with their row indices, and stop reading records they do not change. The range file gains a row list. It is a transient file, so the store's format does not change.
      • The streaming commit takes the other rows from the committed store. An iteration that updates a fraction f of the rows then reads the store about once and writes it about 1 + f times, instead of twice each.
      • No switch between dense and sparse is needed: a worker that updated every row writes them all.
      • The polish overlay (read_pending_range) then reads the discrete pass's sparse range.
    • Incremental sums (a format version three) are not planned.
      • The global section would keep real64 sums and counts per half. A commit would subtract the replaced rows and add the new ones instead of summing every row.
      • With the streaming commit the sums cost nothing. The candidate must be a complete file before its atomic publication, so every row passes through the commit anyway. Version three would pay only if the copy bypassed the process (a file-system copy), which is not portable.
      • Should measurements ever call for it: the sums are valid only for the active set and half labels they were formed under. The store would record an FNV digest of the two (SIMPLE has no project generation counter). Any change of the digest forces a full reduction, and so does a fixed number of commits, so rounding in the running sums cannot accumulate. Every existing store would be rebuilt once.
    • Measure first. Whether the sparse ranges are worth doing depends on how much of an iteration the store transaction takes after the streaming commit. The transaction is timed in its three places, in SIMPLE's benchmark format:
      • the candidate preparation (the copy), in the refine2D and refine3D strategies;
      • the commit phases inside commit_sigma2: the range merge, the reduction, the science validation and the publication;
      • the workers' record read and range write, in the matcher benchmark files.
    • Today's coverage. The refine3D strategy file has a "group-sigma consolidation" line, but it times only the shared-memory commit. The distributed commit and the candidate preparation are untimed. The refine2D strategy writes no strategy file, and gains one in the same format.
    • Context. Each file records the store's particle count, shell count and size in bytes, and the number of rows the update replaced.
    • Test cases. A large project on a spinning disk (the ribosome, with 751,729 particle rows) and one on fast storage. The test machine holds only beta-galactosidase, whose store is a few megabytes, so the run adds the timings and records them there; the ribosome measurement is the maintainer's.
    • Decision. The streaming commit is made in this refactoring (ruled). The sparse ranges follow if the ribosome measurement after it still shows the transaction as a visible share of an iteration.
    • Merges. The chunk merge (concatenate_canonical_states) and merge_selected_canonical_field read each source store whole into memory and write it through its own open and sync, then reduce and validate by re-reading. Instead they copy in fixed blocks through one handle, add to the global sums while copying, and sync once.
