    select2D: interactive class-average selection with a GTK 3 window, written to the project¶

    Partly superseded, 2026-11-25, by select2D_viewer.md: decisions 2 and 4, the mkdir=yes of decision 3 and the executable, router and category of decision 1 are replaced (select2D runs in its own executable simple_viewer, writes nothing until Save selection, and saves a new project into <n>_selection/ as prg=selection does, without selection.txt). The rest stands.

    Status, 2026-11-25: implemented in one pass by the owner's ruling to skip the phased run (Phase 0 ran on the Mac; no tester or Progress entries for Phases 1-6; the decisions below are what the code follows), built and tried by the owner. Restructured the same day, before the first build, into shared GTK modules (simple_defs_gtk, simple_gtk_utils, simple_gtk_draw, simple_gtk_image_grid, simple_gtk_display_panel; the display model renamed simple_stack_display) with select2D as an app on top; the file names of decision 13 are superseded by them. Decisions 2, 6 and 19 ruled by the owner on 2026-11-24. Base: b374f51b4 (clean tree). Supersedes: none. Owner: Dibyajyoti Maity. Depends on: - GTK 3 and gtk-fortran 3.24.49 in every build (cmake/Dependencies.cmake, static library only; validated: yes, builds on the Mac and on Oracle Linux 8 per the owner, 2026-11-24); - the platform test simple_test_exec test=gtk (src/main/gtk/simple_gtk_tester.f90; validated: yes on the Mac with a display); - prg=selection oritype=cls2D as the reference semantics of a class selection (validated: yes, in production).

    1. Why¶

    Class averages are selected today with select2d.py, a 2 075-line Tkinter script outside SIMPLE: it reads the highest cavgs_iter<N>.mrc and classdoc_ranked.txt of a solve2D folder, shows the averages in a zoomable grid with population and resolution captions and a display popup (brightness, contrast, a min/max histogram), and writes a 0/1 selection.txt that the user then feeds to simple_exec prg=selection oritype=cls2D infile=. It needs a Python with Tk 8.6, numpy, mrcfile, Pillow and tkinterdnd2, it re-implements the class document and MRC readers, and the selection reaches the project only through a second program. select2D moves it into SIMPLE as a commander: it makes an execution directory, copies the project there as every project program does, shows the project's class averages from its cls2D and out segments, and writes the selection into that local project copy with the same routine prg=selection uses.

    2. Contract¶

    • select2D is a simple_exec program (decision 2): simple_exec prg=select2D projfile=<p>.simple. With the default mkdir=yes, params%new creates <n>_select2D/, enters it and copies the project there (setup_execution_context, simple_parameters_phases.f90); every read and write of the run is on that copy. The input project is never written.
    • A saved selection has exactly the effect of prg=selection oritype=cls2D infile=<the same 0/1 file> with the same append: os_cls2D state, then map2ptcls_state(append) into ptcl2D, ptcl3D and cls3D, through one shared routine (decision 5). The selection.txt written beside the project reproduces the selection with prg=selection.
    • prg=selection is byte-identical after the refactor of Phase 1 (its project file, at one thread, on the Phase 0 fixture).
    • Off-state: no other program changes behaviour. Without prg=select2D no GTK code runs in any executable; the only GTK call before the window is the display check of decision 15.
    • The display maths of decision 9 follow select2d.py number for number; deviations are listed in decision 12.

    3. Decisions and rulings¶

    1. (2026-11-24, proposed) The program is select2D (the 2D naming of solve2D/refine2D), category Class Average Processing (simple_ui_cavgproc.f90), display name "Select Class Averages", router simple_exec_cavgproc.f90. Inputs: projfile and append (existing key, yes|no, default no). No new parameter keys; oritype is set to cls2D by the commander.
    2. (2026-11-24, owner) Executable: simple_exec links SIMPLE_GTK_LIBRARIES, so every node that runs simple_exec needs the GTK 3 runtime libraries (not a display); GTK is already a build requirement of every build. The alternative is a separate front door (simple_gui with its own router, a case in cmdline%parse, its own prg=list): more machinery, GTK confined to one binary. Phase 0 records whether ldd of a GTK-linked binary resolves on the compute nodes; if not, this decision is reopened (stop condition).
    3. (proposed) The commander: set mkdir=yes and append=no when absent, set oritype=cls2D, check the display (decision 15), then build%init_params_and_build_spproj(cline, params) (one params%new, one full project read of the copy), build the selection session and the display state, run the window until it closes, simple_end. About 40 lines; the window module is imported inside the procedure (compile-time policy).
    4. (proposed) Writing: nothing is written until the user presses Save selection. Save applies the states (decision 5) and writes the four changed segments cls2D, cls3D, ptcl2D, ptcl3D with write_segment_inside to the local copy, and writes selection.txt (one 0/1 per cls2D row, row order). Closing with unsaved changes asks Save / Discard / Cancel. The front door's job-description write after the commander is the existing deviation of the layering policy (section 8) and is not extended.
    5. (proposed) One routine: sp_project%report_state2cls2D(states, append) in simple_sp_project_cls.f90, beside report_state2mic/report_state2stk, holding the two statements of exec_selection's cls2D branch (os_cls2D%set_all('state', real(states)), map2ptcls_state(append=)). exec_selection calls it; select2D calls it. Its NICE extras (thumbnails, JPEG montages, gui_comm) stay in exec_selection.
    6. (2026-11-24, owner) Initial selection: the project's current states (a visible class with state > 0 starts selected), so reopening shows the saved selection and a fresh solve2D project opens all selected. The script's behaviour (nothing selected) was not chosen.
    7. (proposed) Visible classes follow the script: a class is shown unless its pop is present and 0. Hidden classes count in the totals and are always written 0.
    8. (proposed) Data: the cls2D rows (row index = class) with pop and, when present, res; the stack of the out entry imgkind=cavg, read with read_cavgs_into_imgarr (simple_imgarr_utils). The row count must equal the stack's image count, else THROW_HARD before the window opens. The script's discovery of cavgs_iter<N>.mrc and its classdoc_ranked.txt reader are not ported.
    9. (proposed) Display numbers, from select2d.py: brightness -100..100 %, integer, step 1; contrast 0.1..5, two decimals, step 0.01; min/max inside the stack's finite range, step (range)/1000, min < max, a slider clamps to one ulp short of the other limit; stack range over finite pixels of all classes, a constant stack gets upper = min + max(1, 1e-6·|min|); automatic window = medians, taken separately, of each visible class's 1st and 99.9th percentiles (numpy's linear interpolation) of its finite pixels, classes whose two percentiles coincide skipped, fallback the stack range; histogram of 256 equal bins over the stack range of all classes (hidden ones included), last bin closed; mapping v = mid + c·(x − mid) + (b/100)·span with mid, span of the current min/max, then (v − min)/(max − min) clipped to [0, 1], non-finite pixels 0; the real image is resampled to the tile (Lanczos-3 when shrinking, bilinear when enlarging, as Pillow), clipped, and only then converted to 8 bits with rint(255·v); the display-range box spans the raw values mid + (level − 0.5 − b/100)·span/c for level 0 and 1, clipped to the histogram range. Opening resets min/max to the automatic window; Reset restores brightness 0, contrast 1 and the automatic window.
    10.     6. Acceptance¶

    • Percentile and display mapping: equal to numpy (numpy.percentile(..., method='linear'), the formulas of decision 9 in float64) within 1e-12 relative (oracle), the expected values pasted in the tester with the numpy line that made them.
    • Resampling: a constant image stays constant within 1e-6 (closed form); bilinear enlargement of a linear ramp is linear within 1e-6 (closed form); the output size is the tile size (exact). Agreement with Pillow's Lanczos is reported in Phase 7, not gated.
    • Selection, counts, written states and selection.txt: exact (integers). report_state2cls2D on the fixture equals the two statements it replaces, compared field by field (exact).
    • prg=selection identity: the project file byte-identical to the Phase 0 runs at one thread (measured: Phase 0 runs it twice and records whether the file is deterministic; if not, the exclusions are declared there and frozen).
    • Window: GApplication status 0, at least one draw, the tile area drawn at least at its requested size, the scripted selection on disk after the scripted Save (exact).
    • Reported, not gated (Phase 7, by the owner, on a real solve2D project whose path Phase 0 records): the same visible classes, sort orders and footer counts as select2d.py on the same run; selection.txt of an identical selection byte-equal to the script's; screenshots of the grid and the popover in doc/implementation_notes/planned/select2D_screens/.

    7. Common rules and stop conditions¶

    No new parameter key. No floor, tolerance or assertion relaxed. Fix as you go, with a file table row before the edit. Tests at one OpenMP thread; the display render has no OpenMP region in this plan. Every phase is built and run before it is marked done: the GUI phases need the Mac (gfortran 16, a display) and the Oracle Linux 8 box (gcc-toolset-15, headless, and once over ssh -X).

    Stop and report when: a needed GTK function is missing from GTK 3.22 or from gtk-fortran 3.24.49; a key outside projfile, append, mkdir, oritype would be needed; prg=selection is not identical after Phase 1; a GTK-linked binary does not start on a compute node (decision 2 reopens); a GTK file's compile exceeds 60 s after the split of decision 14 (guessed); a file outside the table needs an edit. Gates no ruling may waive: the fast gate, the prg=selection identity, test=gtk with a display on the Mac.
